# AI for Science 初始大调研 — 2026-09-26

## 1. 这轮调研要回答什么

这不是“最近有哪些 AI for Science 论文”的列表，而是为了建立之后每天可增量维护的 research tree。

核心问题：

1. 过去两年 AI Scientist / scientific agent 到底在反复改什么？
2. 哪些改进其实属于同一类？
3. 哪些节点已经很拥挤？
4. 哪些问题正在形成新的论文簇？
5. 哪些问题仍明显空缺，并适合用公开数据、代码、API、有限 GPU 做研究？

---

## 2. 第一阶段：从 Pipeline Automation 到 Search

较早的 AI Scientist 系统主要证明：

> LLM agent 可以把 literature / idea / code / experiment / analysis / paper 串起来。

代表：
- The AI Scientist
- Agent Laboratory

这里的主要贡献是 **workflow coverage**，而不是每一步内部决策已经可靠。

之后研究明显向 “search” 演进。

### The AI Scientist-v2
用 progressive agentic tree search 管理实验候选。

### ERA
把 scientific software 变成明确可评分的 optimization/search problem。

### SciNav
注意到真实 scientific coding 很多时候没有可靠 ground-truth metric，于是用 pairwise relative judgment 来选择 frontier。

因此这三篇不应分成三个独立方向，而应归在：

```text
Research Search
├─ metric-guided tree search
├─ agentic experiment tree search
└─ relative-judgment-guided tree search
```

真正的下一层问题不是“还要不要 tree search”，而是：

> 搜索什么时候应该换 strategy，而不是继续扩当前树？

---

## 3. 第二阶段：从 Solution Search 到 Goal Search

SAGA 是一个值得单独长枝的变化。

普通系统默认：
```text
objective 已知
→ 搜索最好的 solution
```

SAGA 改成：
```text
观察 optimization result
→ 修改 objective
→ 再优化
```

这意味着 scientific agent 开始质疑“我究竟在优化什么”。

这和普通 self-reflection、tree search 的层级不同，因此应单独放在 **Goal / Objective Evolution**。

但 SAGA 仍没有完全解决更广义的 strategy switching：
- goal 错了？
- method 错了？
- implementation 错了？
- metric 错了？
- evidence 不够？

这仍然需要 failure attribution。

---

## 4. 第三阶段：Hypothesis Generation 已经很拥挤

Co-Scientist 把 hypothesis generation 做得非常完整：

- generation
- reflection
- ranking
- evolution
- scientific debate
- tournament
- test-time compute scaling

并且有真实 biomedical validation。

这说明“多生成几个 hypothesis，再让 critic/ranker 选”已经成为成熟范式。

以后新工作如果只是：
- 多一个 agent；
- 多一轮 reflection；
- 换一种 prompt；
- 加 RAG；
- 加 tournament；

不应该自动长新枝。

更有意义的问题反而是：

1. 选出来的 idea 是否 sound？
2. novelty 是否真的意味着值得执行？
3. idea-stage score 能否预测 execution outcome？

---

## 5. 第四阶段：Idea Evaluation 正在拆成多个独立问题

### Novelty
RND 说明 novelty 可以作为独立 metric 研究。

### Soundness
SoundnessBench 说明 methodology viability 也应单独评价。

### Execution value
Ideation-Execution Gap 进一步表明：
idea 被认为 novel/exciting，不代表真正执行后仍然好。

所以未来不要再把“idea quality”当一个总分。

至少拆成：

```text
novelty
plausibility
soundness
testability
expected utility
execution outcome
```

这也是非常重要的 evaluation-protocol 思想。

---

## 6. 第五阶段：Scientific Coding 已成为很清晰的独立能力

这条线已经形成连续 benchmark：

### ScienceAgentBench
自然语言 scientific task → 自包含程序。

### RExBench
existing paper/code → novel research extension implementation。

### ERA
不是只完成给定 task，而是在 candidate programs 中主动 search 更强 solution。

### SciNav
进一步研究没有明确 score 时如何 search / select。

因此“scientific coding”不是普通 coding agent 的别名。

它包含一条越来越接近科研的能力阶梯：

```text
execute known analysis
→ reproduce scientific workflow
→ implement research extension
→ search new computational method
```

这条线非常适合作为低资源 AI Scientist 研究 sandbox，因为：
- 可执行；
- 可自动评分；
- 可复现；
- 不需要真实 lab。

---

## 7. 第六阶段：Evaluation 正从 Final Output 转向 Verifiable Process

这是目前最明显的趋势。

### AstaBench
强调：
- standardized environment
- controlled tools
- cost accounting
- fair comparison

### FIRE-Bench
强调：
- full-cycle research
- published finding as external ground truth
- claim-level evaluation
- failure taxonomy

### Verification Gap survey
强调：
- code release 不等于 claim verification；
- seeds / traces / novelty verification 仍不足。

### The More You Automate, the Less You See
直接证明：
只看 final paper 会漏掉：
- benchmark selection bias
- data leakage
- metric misuse
- post-hoc selection bias

完整 trace/code 才能发现过程错误。

因此后续 evaluation 研究最值得看的方向是：

```text
Outcome Evaluation
        +
Process Evaluation
        +
Evidence Provenance
        +
Cost / Tool Control
```

而不是单独做一个更强 LLM judge。

---

## 8. 第七阶段：真正闭环与“看起来闭环”需要区分

Robin 的价值在于：
```text
hypothesis
→ experiment
→ raw data
→ analysis
→ updated hypothesis
```

但一个系统只要把输出再次塞回 prompt，并不自动意味着它拥有科学意义上的 belief update。

真正需要显式表示：

- 当前 hypothesis；
- 支持证据；
- 反对证据；
- uncertainty；
- 哪个实验改变了哪条 belief；
- 下一步实验为什么最有辨别力。

因此 **Belief Update / Research State** 应从 generic memory 中独立出来。

## 9. 当前最重要的五个 Open Problems

### P1. Strategy Switching
什么时候停止 A，换 B？

目前 tree search 解决“多搜几个候选”，但没有真正解决“为什么该 pivot”。

### P2. Failure Attribution
失败究竟来自：
hypothesis / experiment / code / data / metric / analysis / evaluator 的哪一层？

FIRE-Bench 可以事后分类错误，但 runtime self-diagnosis 仍没有成熟答案。

### P3. Belief Update
实验结果应该怎样更新 hypothesis state，而不是只生成一段新文字？

### P4. Research State / Provenance
怎样让研究过程可以：
- 恢复；
- 避免重复失败；
- 比较不同路线；
- 审计；
- 验证最终 claim？

### P5. Evaluation Protocol
怎样同时满足：
- contamination-resistant
- executable
- open-ended
- externally verifiable
- cost/tool fair
- trace-aware

这是一个比“选什么 benchmark”更大的问题。

## 10. 对后续日更的直接约束

从今天之后，新论文默认不创建新方向。

### 加入已有节点
如果只是同一 Research Problem 下的新 mechanism / stronger evidence。

### 新增子节点
只有当它改变了解法类别。

例：
- 普通 tree search → relative-comparison-guided search，可以新建机制子类。
- fixed objective → autonomous objective evolution，可以新建机制子类。

### 新增主分支
只有当它提出了此前树里没有的 Research Problem。

### 不进入正式树
- 只换 base model；
- 只增加 agent 数；
- 只增加 RAG；
- 只加常规 tool；
- 只提升 prompt；
- 没有公平 baseline / ablation；
- 结果只能说明“系统跑通了”，不能说明机制有效。

---

## 11. 当前最值得连续追踪的三条线

### 线 1：Strategy Switching → Failure Attribution → Meta-reasoning
原因：目前大量系统会 search，但还不真正会诊断研究失败并改变研究策略。

### 线 2：Evaluation Protocol → Verifiable Discovery → Provenance
原因：AI Scientist 的核心瓶颈正在从“能不能生成 research output”转向“这个 claim 凭什么可信”。

### 线 3：Scientific Coding / Simulation Sandbox
原因：最适合在没有 wet lab、没有大规模本地训练的情况下研究 AI Scientist methodology，并且天然支持 executable evaluation。
