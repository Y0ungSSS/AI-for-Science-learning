# 第二轮大调研：Corpus Expansion → Mechanism Clustering → Research Tree Reconstruction

日期：2026-09-26。它取代 [Seed Map v0](初始大调研_2026-09-26.md) 作为以后日更的 **baseline corpus**；Seed Map 留存为可追溯的历史判断。完整条目在[论文语料库](论文语料库.md)，结构结论在[研究树](研究树.md)，精选代表在[论文池](论文池.md)。

## 1. 边界与方法

**问题**：看似不同的 AI Scientist / scientific agent 工作，实际改变了哪一层决策或证据？本轮以 AI Scientist **方法学**为范围；只把领域 agent 纳入能说明通用机制、可执行评测或实体反馈的案例。普通 medical/business/web research agent、只增加 RAG 或多角色的系统不计入有效语料。

| 步骤 | 本轮实际操作 | 防误读措施 |
|---|---|---|
| Seed | 逐字阅读原有 `调研/` 五个文件及代表论文清单 | 原分类仅作假设，不沿用其“空白/成熟”结论。 |
| 多关键词广搜 | 用 22 组 arXiv 标题/主题组合（AI Scientist、scientific agent、hypothesis、coding、simulation、memory、benchmark 等）取得 548 个去重 arXiv 条目；再按重要 anchor 精确补 21 个，工作检索集共 569 条 | 569 是机械检索量，**不是**569 篇相关论文；标题/摘要进行人工范围筛选。 |
| Related work / 引文边界 | 检查 [FIRE-Bench 原文相关工作及协议](https://arxiv.org/html/2602.02905v2)、[AstaBench 原文](https://arxiv.org/abs/2510.21652) 对 replication、metric-driven discovery、paper-generation 的对照；沿 Seed 提示核查 SAGE、EvoScientist、EvoMaster、HypoForge、CORAL、MLEvolve 等 | 综述/相关工作只作发现线索；条目回到 arXiv 原文或 Nature 正式页。 |
| Gap search | 针对 pivot、failure attribution、belief、research state/provenance、trace/process、model/scaffold 继续定向查询 | 发现存在直接工作时撤销“完全没有”的判断。 |
| 核验与归类 | 逐条对照原始标题、日期、摘要、可访问 URL；为每项写 Problem、Mechanism、Compared with、Genuine addition 和 Status | 多数候选达到**原文摘要级**核验；协议深度来自选定原文正文。未逐篇验证的正式 venue 不填写。 |

**结果**：112 篇进入逐条筛选表；107 篇有效机制候选（**ANCHOR 40、SUPPORTING 46、WATCH 21**）；5 篇为范围/冗余排除判例。按 arXiv 首版年份及 ERA 计，2024 年 11 篇、2025 年 26 篇、2026 年 70 篇；Co-Scientist、Robin 的 Nature 正式出版为 2026 年，因此语料表显示正式年份。40 篇 anchor 加 4 篇 supporting 留在长期[论文池](论文池.md)。

在这 107 篇有效语料上形成 **9 个一级 Research Problem、29 个机制/决策簇，以及 8 个评测层级或协议轴**。一级问题为：A 科学构想、B 执行前决策、C 研究搜索与策略、D 自演化、E 科学执行、F 结果/失败/信念、G 研究状态/来源链、H 评测与验证、I 人机协作。每篇只按主要贡献挂一次；交叉作用在树中说明。

## 2. Seed Map v0 哪些判断被推翻或修改

| Old structure / 判断 | 新证据 | New structure / 判断 |
|---|---|---|
| A3 把 novelty 放在 ideation 下，B 把 idea quality 混合评分 | [RND](https://arxiv.org/abs/2503.01508)、[SoundnessBench](https://arxiv.org/abs/2605.30329)、[Ideation-Execution Gap](https://arxiv.org/abs/2506.20803)、[IdeaAMBIG](https://arxiv.org/abs/2609.10539) 分别测新颖性、方法有效性、执行后价值与实现规格。 | A 专管生成；B 独立为 novelty、soundness、execution value/readiness、ranking 四簇。A3 的 novelty 移入 B1。 |
| C2 把 AI Scientist-v2、ERA、SciNav 一起叫 tree search | [v2](https://arxiv.org/abs/2504.08066) 的实验分支、[ERA](https://www.nature.com/articles/s41586-026-10658-6) 的可评分程序、[SciNav](https://arxiv.org/abs/2603.20256) 的相对比较，搜索空间和选择信号不同。 | 分 C2 可评分种群、C3 比较选 frontier、C4 多轨迹/回退；“tree search”只描述容器，不是统一机制。 |
| C3 以 backtracking/plateau 贴近 strategy switching | [PrimeScientist](https://arxiv.org/abs/2609.17846) 把剩余预算写入选择政策；[SAGE](https://arxiv.org/abs/2606.31478) 把失败原因映射到不同修改层；[SAGA](https://arxiv.org/abs/2512.21782) 改 objective。 | C5 资源策略/pivot、C6 目标演化分开；回退是动作，不凭动作本身推断策略已改变。 |
| 原树缺“自演化”一级问题 | [EvoScientist](https://arxiv.org/abs/2603.08127)、[HypoForge](https://arxiv.org/abs/2608.25770)、[Test-Time Tool Evolution](https://arxiv.org/abs/2601.07641)、[CORAL](https://arxiv.org/abs/2604.01658) 改的分别是经验、技能/工具、协作/政策。 | 新增 D；分经验记忆、技能/工具、工作流/政策。单纯“有 memory”不算自演化。 |
| E3 failure attribution 被写成几乎空白 | [SAGE](https://arxiv.org/abs/2606.31478) 直接提出运行时多假设归因与干预路由；[FIRE-Bench](https://arxiv.org/abs/2602.02905) 为事后阶段归因；[LabRobFail](https://arxiv.org/abs/2607.23704) 测实体故障定位。 | F2 为 **emerging**，不是空白；跨层真值、组合故障和修复因果收益仍 sparse。 |
| E4 belief update 只有 Robin 的闭环描述 | [BayesEvolve](https://arxiv.org/abs/2606.30335) 显式预测性信念与不确定性，并在黑盒优化中检验；Robin 有实体实验反馈。 | F3 保留独立节点；明确“优化测试床的显式 belief”尚非真实科研通用信念更新。 |
| F2/F3 把 memory、research state、provenance 靠得太近 | [XScientist](https://arxiv.org/abs/2607.12301) 的类型化状态对象、[Data-to-Paper](https://arxiv.org/abs/2404.17605) 的信息回溯、[OpenDiscoveryTrace](https://arxiv.org/abs/2609.09203) 的过程记录解决不同任务。 | G1 经验记忆、G2 可恢复研究状态、G3 claim–evidence provenance；有 trace 不代表 claim 为真。 |
| G 把 benchmark 名称作为主组织线 | [ReplicationBench](https://arxiv.org/abs/2510.24591)、[RExBench](https://arxiv.org/abs/2506.22598)、[FIRE-Bench](https://arxiv.org/abs/2602.02905)、[ResearchClawBench](https://arxiv.org/abs/2606.07591) 的可见信息和真值不同。 | H 按 knowledge/component → reproduction → extension → rediscovery → discovery → process/cost 分层，并单列评测协议矩阵。 |
| Model vs Scaffold 是“明显空缺” | [AstaBench](https://arxiv.org/abs/2510.21652) 控制工具与成本，跨 agent 类；[Ideation Arena](https://arxiv.org/abs/2608.29696) 跨模型和架构；Robin 做检索 agent 消融。 | H8 改为**部分已有、严格因果分解不足**。真正稀缺的是同模型、同工具、同 judge、同预算的完整 `model × scaffold` 设计。 |

## 3. 最拥挤的五个区域

这里的 crowded 是**基础机制重复**，并不抹平论文在任务、领域或验证强度上的区别。

1. **文献检索支撑的 idea 生成**：ResearchAgent、IdeaSynth、LitPivot、HypER 等都把文献反馈注入构想。LitPivot 的动态上下文与 HypER 的来源链值得保留，但“多检索后多生成”不能再长主枝。
2. **多候选＋批评/辩论/排序**：Co-Scientist 已覆盖生成、反思、排名、演化和实验验证；后续简单添加 agent/critic/tournament，多是已知机制的新组合。IDEAgent 的显式质量—多样性目标则是可区分增量。
3. **局部代码/方案优化**：The AI Scientist、ERA、AlphaEvolve、DeltaEvolve、Aster 等都在反馈评分下改写候选。差别应写成评分器、分叉和预算，而不是系统名；真正跨方法族 pivot 少得多。
4. **笼统“自演化＋记忆”**：STELLA、S1-NexusAgent、EvoScientist、EvoMaster、Kosmos 等常用此名词，但真正变量可能是经验、工具、技能或 harness。若没有跨任务时序对照，新增“self-evolving”标签不能说明机制有效。
5. **静态结果/单 judge 评测**：IdeaBench 类、proposal 判断和最终论文审稿方案很多；同质点是静态输入＋输出评分。AstaBench、FIRE、Reconstruction、OpenDiscoveryTrace 的价值在协议差异，不应归入这个拥挤子类。

## 4. 五个值得研究的稀缺问题：搜索后再判断

| 问题 | 本轮找到的直接工作 | 判断与可证伪下一步 |
|---|---|---|
| **Strategy switching** | PrimeScientist 管预算分配、SAGE 管归因后修改层级、SAGA 管目标演化。 | **不是空白，完整跨层 pivot 仍 sparse**。在同模型/工具/预算下构造“代码可修、实验该换、目标该换”的混合任务，看系统是否按原因选择正确层级。 |
| **Failure attribution** | SAGE 是运行时归因锚点；FIRE 是事后四阶段 taxonomy；LabRobFail 是实体执行故障。 | **emerging**。要给植入的组合故障提供真值，比较 free-form reflection、oracle 归因与系统归因，并验证修复是否真的因诊断而成功。 |
| **Belief update** | Robin 的数据反馈、BayesEvolve 的显式信念；XScientist 是状态记录，不能算概率信念。 | **真实科学任务 sparse**。要求 agent 在见到实验前记录预测概率，随后在多轮模拟/代码实验中测 calibration、信息增益和决策收益。 |
| **Research state / provenance** | Data-to-Paper、XScientist、Arbor、HypER、OpenDiscoveryTrace 等，说明状态表示已成活跃方向。 | **状态表示 emerging；完整 claim 链核证 sparse**。随机移除/篡改数据、配置或负结果，测 claim 是否能被追溯并阻止错误结论。 |
| **Evaluation protocol** | AstaBench、FIRE、ResearchClawBench、Reconstruction、InfiniteScienceGym、OpenDiscoveryTrace 等。 | **论文不稀少，组合条件仍稀缺**：隐藏任务、动态防污染、真实执行、独立真值、轨迹、人审、工具/成本公平同时成立的协议未形成共识。做同一任务的协议变量消融，而非再加一套静态题。 |

额外跨线：**Model vs Scaffold** 已有局部对照，但多论文换模型、检索、工具、搜索预算和 judge 的同时变化，仍会把“系统分数提升”误读成“新机制奏效”。

## 5. Evaluation protocol 核查重点

本轮最清楚的对照是：RExBench **给**论文及代码，让 agent 做 extension；FIRE-Bench **不给**原研究方法和结论，让 agent rediscover；ReplicationBench 要求按既有方法复现；Robin 的实体实验验证则是真实场景案例。它们测量的能力不同，分数不可直接排序。

进一步核对 [FIRE-Bench 正文](https://arxiv.org/html/2602.02905v2) 后，重要边界是：任务给高层问题和数据，**不是**完全禁止 web；作者通过指令与轨迹检查未见 agent 直接找原文，但承认对 proprietary agent 技术性黑名单困难。原文用固定 LLM 抽取原子 claim，再对照论文结果；报告 API 成本及三次运行，无硬运行时上限；用知识截止时间和任务难度分层分析污染，未发现强的系统性污染证据。它仍不是形式上保证无污染的隐藏测试。

[AstaBench 正文](https://arxiv.org/abs/2510.21652) 明确控制生产级搜索工具、报告代理类别与成本，并用固定价格快照保持成本可比；其 2400+ 问题覆盖多层科研能力，不能把总分直接理解为“发现新科学”。[The More You Automate, the Less You See](https://arxiv.org/abs/2509.08713) 的受控错误研究说明只读最终论文会漏查过程失误。其余矩阵中未查到的统一预算/工具或源码可见性，一律保留“待核”，不推断。

## 6. 下一次日更如何使用本基线

新论文先写进 corpus 的合适机制簇；比较同簇 anchor 的**变量变化**、同预算证据与可见信息。若只有分数/模型/角色数变化，保留 SUPPORTING 或 WATCH。若能改变问题、决策规则、证据状态或评价真值，才更新研究树；若推翻本报告的 crowded/sparse 判断，必须写出被推翻的旧判断、原始证据和新判断。

## 7. 核验边界

本轮没有运行论文代码、复制论文实验或重做临床/物理实验。**原始条目核验**证明标题、年份、摘要和链接存在；**机制归类**是对这些原始信息的比较综合；**科学有效性**仍以论文报告和将来的独立复现为界。对新近 arXiv 草稿只用 WATCH 或保留适用范围，不能因发布时间新而自动提升锚点。
