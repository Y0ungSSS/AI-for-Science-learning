# AI for Science 问题树（Problem Tree）

> **读这棵树选问题；读[研究树](研究树.md)看已有解法。** 本文件从截至 2026-10-06 的[机制树](研究树.md)、[119 篇语料](论文语料库.md)与[第二轮大调研](第二轮大调研_2026-09-26.md)归纳而来；不是独立实验结论，也不意味着所有 gap 都已被全领域检索证实。
>
> 目标：帮助发现研究灵感、判断与前作差异，并把值得尝试的想法交给 Codex 做**小规模、可证伪的实验**。问题不因当天有新论文而自动增加。

**2026-10-21 总体判断**：最近已核实的机制工作显著加密 C5/F3（诊断、可识别性、开放假设）、D1–D3（跨轮改进与遗忘）、G3/H7（证据因果依赖）和 E4/E5（逆向目标律、实验环境自建）等方向。**Q1–Q9 仍适用，没有证据要求新增 Q10**。新论文的证据层级、前作差异及限制详见[研究树 2026-10-21 全局复审](研究树.md#2026-10-21-双树全局复审机制证据去重补录25-篇)。原来的 119 篇历史语料数不因此更新；双树是唯一主动维护的研究状态。

## 一眼看懂：问题在哪里？

```text
AI Scientist 怎样才算可靠地做科学？
│
├─ Q1 科学构想：提出的想法新、对、值得做吗？
├─ Q2 研究控制：什么时候继续、回退、换方法或改目标？
├─ Q3 故障诊断：失败源于假设、实验、代码、数据还是评价？
├─ Q4 证据更新：实验结果真的改变了信念吗？
├─ Q5 研究状态：长程研究能记住什么，并证明结论来自哪里？
├─ Q6 科学执行：代码、仿真、软件产物何时构成科学证据？
├─ Q7 可信评测：怎样测科学发现而不是测答题与刷分？
├─ Q8 自我改进：跨轮经验何时真的提升方法，而非仅增长上下文？
└─ Q9 人机协作：哪些关键决策应自动、哪些应请求专家？
```

**问题与方法不要混淆**：`tree search`、`multi-agent`、`RAG`、`critic`、`memory` 是候选方法，不是天然的新科研问题。一个方法可以服务多个问题；一个问题也可能存在多条竞争方法路线。

**初步关注顺序（研究规划，不是论文结论）**：Q2／Q3／Q7 最适合从可执行 benchmark 和公开代码切入；Q4／Q5 可以作为后续延伸；Q6 可提供无需真实实验室的实验载体。状态标签：**拥挤**＝本样本中同类方案多；**活跃但证据缺口**＝已有直接工作，关键对照不足；**局部稀缺**＝在所检查语料中较少见，不等于全球没有论文。

## Q1. 科学构想怎样从“新颖”变成“值得执行”？

**问题结构**
- Q1.1 生成：文献重组是否会造成构想同质化？多样性是否改善下游结果？
- Q1.2 评价：`novelty ≠ soundness ≠ feasibility ≠ expected utility`，不能由单一分数代替。
- Q1.3 选择：pairwise / tournament / absolute score 哪种选择信号在何种条件下可靠？
- Q1.4 稳健性：judge、prompt、retrieval、reasoning budget 改变会不会使同一想法被判成不同等级？

**已见证据**：[Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y) 系统化生成／批评／排名／演化；[RND](https://arxiv.org/abs/2503.01508) 聚焦 novelty；[SoundnessBench](https://arxiv.org/abs/2605.30329) 聚焦 soundness；[Ideation-Execution Gap](https://arxiv.org/abs/2506.20803) 强调必须看执行后价值；[Old Ideas, Novel Problems](https://arxiv.org/abs/2610.02022) 报告 novelty 判定的设计敏感性。

**缺口判断**：idea-generation 的简单编排已**拥挤**；idea evaluator 的校准、可执行价值预测及跨设置稳健性仍**活跃但证据缺口**。对应[研究树 A1–A3、B1–B4、H7–H8](研究树.md#rt-b)。

**可测试的问题**：同一批 idea 和人工／可执行参照保持不变，只改变 judge prompt、模型、检索和预算，评价 verdict flip rate、ranking correlation、校准与 downstream utility。不要把 judge 分数当真值。

## Q2. 研究何时应该换路线，而不只是继续修改？

**问题结构**
- Q2.1 **Local refinement**：A→A′→A″ 是否只在局部徘徊？
- Q2.2 **Rollback**：分支退回是否优于贪心改写？
- Q2.3 **Strategy switching**：是修实现、改实验设计，还是放弃整个 method family？
- Q2.4 **Goal change**：现有 objective 是否本身错了？
- Q2.5 **Stopping / resource allocation**：何时继续试、何时验证、何时停止？

**已见证据**：[The AI Scientist-v2](https://arxiv.org/abs/2504.08066) 有实验树；[ERA](https://www.nature.com/articles/s41586-026-10658-6) 有可评分程序搜索；[SciNav](https://arxiv.org/abs/2603.20256) 用相对比较选 frontier；[PrimeScientist](https://arxiv.org/abs/2609.17846) 涉及预算分配；[SAGA](https://arxiv.org/abs/2512.21782) 改 objective。[Runtime Agent Coordination](https://arxiv.org/abs/2610.00980) 的“切换执行者／能力”不同于 scientific method-family pivot。

**缺口判断**：搜索方案很多，通用的“**诊断原因 → 选择修改层级 → 在固定预算下验证转向收益**”仍局部稀缺。**Backtrack ≠ pivot ≠ change objective**。对应[研究树 C1–C6、D3、H8](研究树.md#rt-c)。

**Codex 实验候选 E1｜固定预算的跨层决策**（优先）
- **任务**：建立可执行的科学代码／模拟小任务集，分别植入实现缺陷、方法族不适配、目标／评分指标错配；让 agent 决定 repair、refine、rollback、pivot 或 stop。
- **对照**：always-refine、固定 tree search、规则路由、oracle 故障层级；保证模型、工具、总 token / 执行调用 / wall time 尽可能一致。
- **记录**：每步观察、选项、选择原因、失败轨迹、切换成本、独立测试集上的成功率和 total cost。
- **能推翻假设的结果**：复杂策略在同预算下不优于简单重试／回退；或收益主要来自额外样本而非决策。
- **前置关口**：先确认任务里确实需要跨层转向，且不同故障类型具可区分的 oracle label；不直接投入长时间训练。
- **2026-10-12 证据与实验补充**：[JANUS](https://arxiv.org/abs/2610.13194) 将执行前预测用于分支排序，但其预测值校准和额外判断成本仍需独立核验。Codex 可固定候选池与执行预算，比较随机选择、执行后贪心、静态预测、在线更新预测；测 predicted-vs-actual gain 的校准、每单位总成本的最终收益与错误剪枝率。

**2026-10-21 证据重审｜Q2：从经验性 pivot 转向诊断性 pivot**

[LLM-IDEA](https://arxiv.org/abs/2610.11253) 将平台期分为 agent 能力限制、可通过现有设计解决的不可辨别、当前观测协议耗尽；[SHELDON](https://arxiv.org/abs/2610.18025) 将假设与观测空间分开探索；[Possibilistic Reasoning](https://arxiv.org/abs/2610.11289) 给条件化统计有效性/停止目标；[Station](https://arxiv.org/abs/2610.08927) 研究无中间 reward 时的持续探索。这些工作说明 **pivot/停止不是无人研究的空白**，真正缺口在决策路由和证据条件的独立验证。

**Codex E1b｜三类平台期与策略转向**：用受控 ODE/线性逆问题构造 A 低模型能力、B 当前设计可解决不可识别、C 观测协议内完全不可识别；固定 20–40 次仿真查询预算，比较随机/局部重试、规则诊断、灵敏度矩阵诊断、oracle 路由。测错误停止率、错误转向率、科学机制 held-out 恢复率、单位正确结论所需查询；**若诊断带来的收益仅来自额外观测或特定 prompt，则否定“诊断器机制独立有效”**。与 [Learning to Outgrow a Theory](https://arxiv.org/abs/2610.07627) 的结构编辑对照，禁止假设测试集候选空间恒包含真解。

## Q3. Agent 能否正确定位失败并做定向修复？

**问题结构**
- Q3.1 失败来自 hypothesis、experiment design、implementation、data、metric、analysis、evaluator 哪一层？
- Q3.2 观测不足时，能否主动设计**区分不同故障解释的诊断实验**？
- Q3.3 多层同时故障如何处理？“工具调用成功但字段缺失”如何发现？
- Q3.4 诊断正确是否真的提高修复效率，而非只生成合理解释？

**已见证据**：[FIRE-Bench](https://arxiv.org/abs/2602.02905) 支持事后阶段错误分析；[SAGE](https://arxiv.org/abs/2606.31478) 提出运行时归因和干预路由；[Silent Failures](https://arxiv.org/abs/2609.26836) 指出工具链边界的信息损失；[ASCEND](https://arxiv.org/abs/2609.32868) 提供 HPC 故障恢复案例。

**缺口判断**：并非空白，属于**活跃但证据缺口**；关键是跨层组合故障的真值和诊断→修复的因果收益。对应[研究树 F1–F2、C5、G3](研究树.md#rt-f)。

**Codex 实验候选 E2｜已知故障注入与归因**
- **任务**：用可复现的科学数据分析脚本注入不同层错误（字段丢失、单位换算、代码逻辑、数据泄漏、无效指标），保留故障注入 manifest 作为 oracle。
- **对照**：free-form reflection、单层 rule-based diagnostic、多假设归因、oracle 归因；保留独立未见故障组合。
- **指标**：故障层定位准确率、诊断实验数量、targeted-repair 成功率、误修率、成本；定位正确≠修复正确。
- **能推翻假设的结果**：定位标签看似准确，但修复成功率／成本未改善。

**2026-10-21 证据重审｜Q3：不要只诊断代码错，还要诊断“目标/指标错”**

[Coupled Harness–Model Evolution](https://arxiv.org/abs/2610.17740) 将“没有所需工具”和“有工具却未调用”分离；[SwarmRSI](https://arxiv.org/abs/2610.20431) 区分假设缺陷与组件缺陷并复用局部正结果。[Same Simulation, Different Evidence](https://arxiv.org/abs/2610.26836) 提供**结果计算正确而读取权威来源失败**的反证，因此 Q3 层级需要显式包含 evidence retrieval / authority selection，而非将所有答错归入推理、仿真或代码。后续关注指标代理失真与跨层复合故障，但仍缺少可独立核实的通用错误目标诊断机制。

**2026-10-23 增量证据｜Q3 失败归因与目标错配**：[DAGLoop](https://arxiv.org/abs/2610.25089) 将设计决策、必要前提与消融测试组成 DAG，避免拆掉前提后错误归因；[Aptamers](https://arxiv.org/abs/2610.24806) 的实体 counter-screen 发现“结合强但非特异”的代理指标陷阱并调整后续策略。**修订**：Q3.1/Q3.2 不只需知道哪层失败，还需验证某设计在**其依赖条件成立时**是否真有预期效果；metric/assay artifact 是独立故障层。原始研究的设计依赖图可能不完整，湿实验的不同轮次 harness 变化也不能归因于单个 LLM 策略。

**Codex E2b（低资源）**：在 3–5 个可执行模拟/ML 小任务预先设置 A 依赖 B、A×B 交互和错误代理评分，比较普通逐项 ablation、依赖保持 ablation、oracle 因果结构。预注册每个设计的预期效应与实验条件，固定候选数和运行次数；指标为错误贡献归因率、真实目标 held-out 改善、额外计算成本。**否证**：依赖保持策略不能比简单联合消融减少错误归因，或仅改善代理分数。

## Q4. 实验反馈是否真正更新科学信念？

**问题结构**
- Q4.1 保存结果与显式更新 belief（预测、不确定性、支持／反证）有何不同？
- Q4.2 遇到与先验冲突的数据，是否承认错、降低置信度？
- Q4.3 能否选择最能排除 competing mechanisms 的辨别实验？
- Q4.4 拟合外部规律是否代表发现内在 mechanism？

**已见证据**：[Robin](https://www.nature.com/articles/s41586-026-10652-y) 形成实验反馈；[BayesEvolve](https://arxiv.org/abs/2606.30335) 用显式信念做优化决策；[WhatWorkedBench](https://arxiv.org/abs/2609.27490) 测实验后预测；[MechBench](https://arxiv.org/abs/2609.35515) 区分现象规律和机制恢复。

**缺口判断**：预测性 belief 已有机制雏形，但对真实科学任务的多轮校准与机制鉴别仍**局部稀缺**。对应[研究树 F3、E4–E5、H7](研究树.md#rt-f)。

**2026-10-18 新证据 → Q4/Q7 接口**：[Evaluating Inquiry Learning](https://arxiv.org/abs/2610.21604) 在有限数学交互环境中同时观察变量选择、推理和假设细化；[Autonomous Science Bench](https://arxiv.org/abs/2610.18449) 则把“测到高价值设计（discovery gate）”与“对未见设计的预测排序（learning gate）”分开。**缺口修订**：不应仅以找到最佳配置说明 agent 真正更新了可泛化的机制信念；需要独立留出集检验实验后预测，以及排除提示式 scaffolding 和额外测量预算的贡献。该结论仅限两篇的受控任务，尚非开放科学通用定理。

**Codex 实验候选 E3｜多假设模拟**
- 用可生成独立观测的简化模拟器，设置多种生成机制；每轮强制 agent **先记录下轮预测和置信度**，再看到结果。
- 比较无状态文本反思、结构化证据表、显式概率 belief；控制实验次数和模型预算。
- 评价 held-out prediction、Brier score／适用时的 log-loss、假设淘汰质量、区分实验效率；避免让模拟器真值进入 prompt。

**2026-10-21 证据重审｜Q4：机制、目标律和证据响应应分开测**

[OptScientist](https://arxiv.org/abs/2610.28562) 恢复的是能够解释最优行为的**隐含目标/约束**，不是单纯拟合动力学；但 inverse optimization / inverse optimal control 已有成熟前作，且行为偏好/最优排序吻合不保证目标唯一可识别。[MechHypoBench](https://arxiv.org/abs/2610.05197) 从观测到开放机制假设，利用隐藏条件的后果检测。[Are We Measuring Scientific Intelligence?](https://arxiv.org/abs/2610.04915) 显示正确答案可能不依赖当轮科学证据。Q4 因此应分别测：① 已给证据的因果使用；② held-out 预测；③ 机制/目标可识别性；④ 数据冲突时的置信度校准。

**轻量可证伪延伸**：用二次规划/带约束线性规划生成最优行为数据，设置两组能产生相同排序但不同目标表达的 world；比较拟合预测、目标式回归、oracle 同值类判定。对不可识别世界要求 agent 输出“等价解释集合”而非自信声称唯一真实律。指标包括选择集外预测、区分实验有效率和过度确定率。与已有逆优化方法作为必要 baseline，暂不立新 Research Problem。

**2026-10-23 关键反证｜Q4 的“反馈被使用”必须先于“反馈有收益”检验**：[When Does Feedback Help?](https://arxiv.org/abs/2610.27632) 在合成电压钳环境中，5 个策略 1200 次 rollout 全部重复固定协议，mask 电流不改变行动；另一任务的策略确实用反馈，但与简单 Bayesian/阈值策略相当。[PEARL](https://www.biorxiv.org/content/10.64898/2026.10.20.760214v1) 和 [Aptamers](https://arxiv.org/abs/2610.24806) 为实体实验中主动获取信息/修改设计提供实例，但不足以替代受控反馈消融。**缺口更新**：真实闭环中的观测依赖与策略质量是两个独立指标，Q4.1/Q4.2 的证据强度上调，通用 belief 校准仍未解决。

**优先 Codex E3b｜反馈因果依赖审计（低资源）**：在小型 ODE/黑盒模拟器预制不同观测对应不同最优实验的 paired worlds；同一决策状态对照 (a) 真观测、(b) mask、(c) 随机置换、(d) 与真值冲突的反事实观测。固定模型、先验、历史、总查询/时间预算，先记录下轮实验选择和概率预测，再看结果。分别报告 **action sensitivity / conditional information gain、held-out prediction/Brier、最优实验质量、误转向率与成本**。**否证**：模型在观测被替换后决策不变却获得高最终分数，说明分数不能支持“反馈驱动”；决策敏感但性能不优于规则/Bayesian baseline，也不能宣称策略更优。

## Q5. 长期研究怎样可恢复、可审计、不过度依赖上下文？

**问题结构**
- Q5.1 episodic memory、skills、研究状态、evidence provenance 是否混为一谈？
- Q5.2 跨轮 failed attempts、决策理由、版本及负结果如何可靠保存？
- Q5.3 从最终 claim 能否追溯数据、配置、代码、实验和证据？
- Q5.4 删除／篡改一段 provenance，系统是否发现结论已不可核证？

**已见证据**：[EvoScientist](https://arxiv.org/abs/2603.08127)、[XScientist](https://arxiv.org/abs/2607.12301)、[Arbor](https://arxiv.org/abs/2606.11926)、[Data-to-Paper](https://arxiv.org/abs/2404.17605)、[OpenDiscoveryTrace](https://arxiv.org/abs/2609.09203)。

**缺口判断**：状态表示**活跃**，完整 claim 核证仍局部稀缺。可以用小项目做 provenance corruption / recovery 实验，无需真实实验室。对应[研究树 G1–G3、D1、H6](研究树.md#rt-g)。

**2026-10-21 证据重审｜Q5：长时记忆的价值不是记录量，而是来源真实性与条件化保留**

[Épi](https://arxiv.org/abs/2610.24944) 将多会话持久研究状态、分支与固定验证器结合；[DrugHarness](https://arxiv.org/abs/2610.23791) 以 applicability conditions 和 source review 筛选可复用技能；[Same Simulation, Different Evidence](https://arxiv.org/abs/2610.26836) 说明**仿真正确不保证引用到权威输出**。将 Q5.3/Q5.4 的 provenance 分成“能追溯”和“决策确实用对来源”两层，二者不是同义词。

**Codex E5｜证据替代消融（优先）**：固定同一批科学计算的正确输出，提供 (a) 完整内联权威日志，(b) 文件检索，(c) 索引检索+显式权威指针，(d) 结构化 claim→source 链；注入名称相近的中间/旧版/不同精度输出，控制相同模型、问题与执行预算。记录 oracle numerical correctness、source selection accuracy、claim-level correctness、false confidence 和额外 token/time；**如果加入 provenance 仅改善可读性、不改善正确引用，不能宣称提高了科研可信度**。此实验是 [Same Simulation](https://arxiv.org/abs/2610.26836) 的独立扩展，不声称首次发现该机制。

## Q6. “科学任务运行成功”何时能够支持真实科学结论？

**问题结构**
- Q6.1 coding、reproduction、research extension、new method search 是不同能力层级。
- Q6.2 simulation 要同时测数值正确性、物理有效性、效率与可识别性。
- Q6.3 科学软件 GUI artifact 正确，是否意味着解释和 claim 正确？
- Q6.4 实体实验中的人类干预与噪声如何进入结论？

**已见证据**：[ScienceAgentBench](https://arxiv.org/abs/2410.05080)、[RExBench](https://arxiv.org/abs/2506.22598)、[ERA](https://www.nature.com/articles/s41586-026-10658-6)、[GPUPhysBench](https://arxiv.org/abs/2609.35639)、[OSWorld-Science](https://arxiv.org/abs/2609.39903)、[Robin](https://www.nature.com/articles/s41586-026-10652-y)。

**缺口判断**：科学编码／可执行基准已**活跃**；从 executable artifact 到 claim verification 的桥梁仍不完整。适合作为 Q2–Q5 的实验环境，而非仅靠增加一个 coding agent 创新。对应[研究树 E1–E5、H1–H5](研究树.md#rt-e)。

**2026-10-18 新证据 → Q6/Q7 接口**：[Into the Unknown](https://arxiv.org/abs/2610.19159) 发现 AI 生成的开放科研 follow-up 可能声称没有实际执行的实验；[Structure Before Intelligence](https://arxiv.org/abs/2610.19507) 用版本化 DAG、验证器和 release gate 管控无效科学产物。**缺口修订**：可执行产物“存在”还不够，必须有从 claim 到数据/代码/运行记录的核对；确定性 gate 应作为 LLM 审查的强基线，同时测误拒/误放，不把局部零误放写成全领域保证。

**2026-10-21 证据重审｜Q6：运行环境与研究结论之间还有两个独立障碍**

[PhysCodeGym](https://arxiv.org/abs/2610.17288) 通过反事实物理干预指出表面逼真但物理机制错误的程序；[Self-Building Labs](https://arxiv.org/abs/2610.23826) 提出了为目标实验自动搭建数字孪生与机器人技能的执行能力构建。后者是 E5 的**执行环境自构建**子方向，而非新一级 Research Problem，涉及硬件安全、校准、人工参与和成本。软件/设备搭好、实验执行成功和科学主张得到验证必须分别记录。

## Q7. 怎样评测“科学发现”，而不是模型背题、刷指标或迎合评委？

**问题结构**
- Q7.1 **测量对象**：knowledge QA／component／reproduction／extension／rediscovery／open-ended discovery 不能互换总分。
- Q7.2 **可见信息**：目标论文、方法和结果是否隐藏？web 是否开放？
- Q7.3 **独立真值**：任务可执行吗，claim 有外部验证吗，机制识别有探针吗？
- Q7.4 **评判稳定性**：judge／prompt／retrieval／budget 改变是否翻转结论？
- Q7.5 **协议公平**：相同模型、工具、搜索预算、硬件和成本？
- Q7.6 **防污染与反作弊**：静态题、动态题、轨迹和可见反馈各有什么攻击面？

**已见证据**：[AstaBench](https://arxiv.org/abs/2510.21652) 提供工具／成本控制；[FIRE-Bench](https://arxiv.org/abs/2602.02905) 使用已发表研究的外部参照做 rediscovery；[RExBench](https://arxiv.org/abs/2506.22598) 把 research extension 单列；[SoundnessBench](https://arxiv.org/abs/2605.30329)、[MechBench](https://arxiv.org/abs/2609.35515)、[Old Ideas, Novel Problems](https://arxiv.org/abs/2610.02022) 覆盖不同评测偏差。

**缺口判断**：benchmark 数量不稀少；同时满足开放性、执行、独立验证、防泄漏和公平成本的协议仍**证据缺口**。对应[研究树 H1–H8](研究树.md#rt-h)。

**2026-10-18 评测边界更新（见[研究树 H7](研究树.md#rt-h)）**

- **Discovery ≠ Learning**：[Autonomous Science Bench](https://arxiv.org/abs/2610.18449) 让实验选择与未见设计预测通过两个独立关口；补强 Q7.1/Q7.3，不能用单一 campaign 成功率替代泛化能力。
- **完成科研稿 ≠ 证据完整**：[Into the Unknown](https://arxiv.org/abs/2610.19159) 的开放 follow-up rubric 与 integrity check 把 paper–execution 不一致显式暴露；补强 Q7.3/Q7.6。
- **验证通过 ≠ 推理改善**：[ClaimScope](https://arxiv.org/abs/2610.21581) 的 schema-only 后处理匹配验证器带来的安全完成提升；[Structure Before Intelligence](https://arxiv.org/abs/2610.19507) 在受控发布任务中未测出 LLM 的独立收益。应单列 formatting/schema repair、确定性 validator、LLM review 三种贡献。两项研究任务范围较窄，不据此否定所有 LLM 审查。

**优先交给 Codex 的低资源实验 E4b｜科研主张的分级发布核验**
- **任务**：选公开科学分析脚本/小型 ODE 模拟，预制正确产物和含数据版本过期、单位/数值错误、遗漏必要步骤、结论超出证据范围的成对产物，保留独立 oracle。
- **因子对照**：① 不验证；② 仅 schema/格式修复；③ 确定性测试+provenance gate；④ LLM 评审；⑤ ③+④。固定输入、模型、token、执行次数和可见证据，另外记录验证器成本。
- **指标**：false release、false rejection、claim-level accuracy、证据链覆盖、成本；分开评价局部通过和科学结论闭合。用未见故障组合验迁移。
- **可证伪点**：若简单 schema/rule-based gate 已与 LLM 审查同等有效，不能把增加 critic 当新机制；若验证器误拒显著，不能把“零放行”当整体最优。

**Codex 实验候选 E4｜协议变量消融**
- 固定同一批可执行任务、agent 和总预算，仅依次改变：judge prompt、source-paper 可见性、是否评轨迹、是否启用独立检查。
- 先定义外部可复核的正确性（代码测试／模拟已知机制），再观察 benchmark 排名翻转与 shortcut 率。
- 指标：rank stability、false-pass、false-reject、成本、跨任务泛化。若改变协议会轻易改变榜单，则“某系统更会科研”的结论需要限定协议。

**2026-10-21 证据重审｜Q7：新评测应防止“学会答案但没用数据”**

[AutoSciBench](https://arxiv.org/abs/2610.05140) 提供随 agent 失败轨迹演化的 benchmark 配方，但困难度增加不等于真值和真实性提高；[Are We Measuring Scientific Intelligence?](https://arxiv.org/abs/2610.04915) 直接以保留/撤除/反转证据检测数据依赖；[DrugTargetWorld](https://arxiv.org/abs/2610.09558) 通过隐藏模拟因果结构构造可评分真值；[RSI-Forge](https://arxiv.org/abs/2610.09426) 把论文复现映射成可执行环境并承认 shortcut/reproduction fidelity 仍成问题。**更新优先级**：真值可靠与 claim–evidence 因果连接优先于更多题和更高难度。

Codex 协议扩展：对于每个 benchmark 条目同时提供原证据、经预注册统计检验的证据撤除/反转、以及确定性和 LLM 评分；先测 data-responsiveness，再测单次任务分。若模型在反向证据条件下仍输出旧答案而总分不变，说明该分数不是稳健的科学证据理解指标。

**2026-10-23 评测协议更新｜Q7：分开检验 verifier 正确、科学推理与工程分数**：[VeriEvolve](https://arxiv.org/abs/2610.29005) 先合成并校准可执行 evaluator、每轮冻结、轮次间以反事实终态修订；其外部 held-out 一致性 113/122，说明自建题上满分不等于独立可靠。[Agent4Sci](https://arxiv.org/abs/2610.28763) 的 20 个科学 ML benchmark 表明，模型改进可主要来自通用工程技巧而非新科学 insight；插件使分数进一步提高，也需拆分 model/scaffold 与资源贡献。[Distributed Biological Reasoning](https://www.biorxiv.org/content/10.64898/2026.10.15.759436v1) 的隐藏原论文、held-out 扰动和专家盲评值得借鉴，但多 agent 与总成本混杂。**Q7.3/Q7.5 优先级上调**：外部真值校准 + 科学新颖性分类 + 同成本审计，不能用同一个分数代替。

**Codex E4c（协议增补，不另立问题）**：固定 20–30 个可执行科学分析故障，先独立标注正确状态和错误主张；用同一数据比较自动生成 verifier、人工规则 verifier、冻结后经反事实修订的 verifier，统计 held-out false-pass/false-reject 与版本漂移。另将最终改进标注为修 bug/调超参/改模型结构/提出新科学假设，盲评其证据支持；所有 agent 比较使用相同模型、数据划分、执行次数和总 token/时间。

## Q8. Scientific Agent 如何从跨轮经验中真正学会更好的研究策略？

**问题结构**
- Q8.1 保存失败摘要是否提高下一任务的决策，而不是只增加 token？
- Q8.2 技能／工具自动生长能否迁移到新问题？
- Q8.3 工作流／调度规则演化，与换更强 base model 的贡献能否区分？
- Q8.4 坏经验、工具版本改变和分布外任务是否导致负迁移？

**已见证据**：[EvoScientist](https://arxiv.org/abs/2603.08127)、[HypoForge](https://arxiv.org/abs/2608.25770)、[Test-Time Tool Evolution](https://arxiv.org/abs/2601.07641)、[CORAL](https://arxiv.org/abs/2604.01658)、[Runtime Agent Coordination](https://arxiv.org/abs/2610.00980)。

**缺口判断**：泛称 self-evolving 的文章**较拥挤**，严格时间切分、无记忆对照、跨任务迁移与机制归因较少。对应[研究树 D1–D3、G1、H8](研究树.md#rt-d)。

**2026-10-12 证据与 Codex 小实验**：[Humanize MLE Agents](https://arxiv.org/abs/2610.13494) 提示旧 harness 可能随 backbone 升级变成负收益；这改变了 Q8.3 的评估优先级，但不是新问题。固定一组小型可执行研究任务和总预算，比较原生单会话、同模型上下文重置、同模型双会话接力、异模型交替，以及旧定制 harness × 新旧模型；记录每次实验收益、token/时间、最优产物是否保留和跨任务迁移。**否证条件**：在同预算下重置/交替并无增益，或增益仅来自更多执行次数。

**2026-10-21 证据重审｜Q8：记忆、遗忘、技能、参数更新是不同机制**

[Scaling Discovery Requires Forgetting](https://arxiv.org/abs/2610.20563) 给出主动删除历史可能提升搜索的直接反例；[SwarmRSI](https://arxiv.org/abs/2610.20431) 指向保留失败实验中的局部可用组件；[DiscoveryRSI](https://arxiv.org/abs/2610.23839) 做贡献级信用与 harness replay；[HarnessTTT](https://arxiv.org/abs/2610.17370) 冻结 executor 学 harness；[Coupled Harness–Model Evolution](https://arxiv.org/abs/2610.17740) 分阶段演化工具与模型；[MELD](https://arxiv.org/abs/2610.24454) 则联合学习协调与个体策略。这些都可挂 D1–D3，**不构成无人研究的新问题**；缺口是控制住执行预算的因果拆分及真实任务的迁移可靠性。

**Codex E6｜受控遗忘与可复用失败组件**：在公开的小型可评分算法/科学仿真搜索任务中，设置完整历史、摘要、周期删除（只保留 best artifact）、保留最佳产物+失败组件标签 4 组；固定同一模型、初值、seed、总 evaluator calls、时间和候选池，测 held-out 最佳收益、回访重复率、负迁移与成本。否证：主动遗忘的表面收益来自额外 budget、删掉历史后的 seed 偶然性，或不能迁移到保留真实研究状态的任务。

**2026-10-23 增量证据｜Q8：经验“复用单元”与独立迁移验收**：[ExpEvolve](https://arxiv.org/abs/2610.29303) 从已评分程序抽取可解释 idea factors，并将其用于跨程序结构的探索控制；这是 [CausalEvolve](https://arxiv.org/abs/2603.14575) 的扩展，且高层因子与分数关联不等于因果发现。[ScienceClaw](https://arxiv.org/abs/2610.08691) 在固定基础模型下要求 source-task replay 与独立任务收益才接受 Skill/Operator 更新。**Q8.1/Q8.2 缺口细化**：区分完整程序、失败组件、文本经验、idea factor、可执行 skill 五种经验单元；以独立任务迁移、负迁移和总推理/评测成本判断是否真进化。

**Codex E6b（接续 E6）**：选小型程序搜索或可评分仿真任务，固定初始 archive 和 40–80 次 evaluator 调用，比较程序复制、文本摘要、组件重组、idea-factor 标签引导、源任务 replay+独立测试门控；额外 LLM 标注调用计入总成本。以 unseen task gain、误接受 skill 率、重复探索率和成本作判据。若收益来自更多 LLM 调用或标签与 held-out 无关，则不认定机制独立有效。

## Q9. 人类科学家应该在什么时候介入？

**问题结构**
- Q9.1 人类负责定 research question、批实验、解释冲突证据，还是最后签名？
- Q9.2 Agent 能否在高风险／高成本／证据冲突时请求专家，而非定期打断？
- Q9.3 同预算下，选择性专家介入能否优于全自动或固定阶段审查？

**已见证据**：[Agent Laboratory](https://arxiv.org/abs/2501.04227)、[Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y)、[AIMC](https://arxiv.org/abs/2608.28637)、Robin。完整真实实验常有人工步骤，不能误称无人闭环。对应[研究树 I1–I2、H5](研究树.md#rt-i)。

## 选题交给 Codex 前的统一关口

只有通过以下检查，才从**灵感**升级为**实验候选**：

| Gate | 必须回答 |
|---|---|
| G0 研究问题 | 具体失败模式是什么？已有论文做到哪一步？为什么不是已有机制换名字？ |
| G1 可证伪假设 | 什么观测会证明这个 idea 不成立？ |
| G2 基线与协议 | 最相近 2–3 条路线、最简单 baseline、相同模型/工具/预算、公平独立真值是什么？ |
| G3 最小实验 | 是否能用公开代码／合成故障／模拟先验证？是否避免长时 GPU 训练和实体实验？ |
| G4 结论边界 | 成功能证明什么，不能证明什么？失败应回写哪个问题节点？ |

**给 Codex 的最小实验 brief**：问题编号 + 对应研究树节点 + 可证伪假设 + 最相关论文链接 + task / dataset + baselines + controlled variables + metrics + failure criterion + execution budget + evidence artifacts。缺任何关键项时先补研究设计，不直接启动长训练。

## 每日增量维护规则（只维护这两棵树）

1. 先读[研究树](研究树.md)已有机制和本问题树的 gap，再查 24–72 小时论文；按**首次提交／版本日期**判定“新”，不能把旧稿重推当成新论文。
2. 每个候选先判断：不收录／补已有机制证据／更新已有问题的 gap 结论／只有真的改变问题定义时加节点。
3. 若只改善模型、prompt、普通 RAG、角色数、或没受控对照，不凭包装长枝；若有反例必须修正旧的“拥挤/稀缺”判断。
4. 每篇进入树的新论文需包含 **Problem / Core mechanism / Compared with / Tree position / Genuine addition / Evidence limitation** 和原文链接。
5. **两棵树之外的旧文件只作历史证据**；每日不新增论文清单、日报、单篇摘要。没有重要增量时不改文件、只报告“无结构性更新”。
6. 更新顺序：**先研究树（证据与方法差异），再问题树（是否改变 gap、优先级或实验）**；绝不因为新增一篇论文就自动生成一个新“研究问题”。

**维护记录**：2026-10-08 将原有 9 类机制的研究缺口整理为 Q1–Q9，并将 Q2/Q3/Q4/Q7 转换为可交给 Codex 的小实验构想。尚未因此运行任何实验；推荐优先级是选题建议，不是已验证科研结论。


**2026-10-17 Q7 证据**：[PhysClosureBench](https://arxiv.org/abs/2610.21767) 区分局部得分与科学结论完整性；[SciΠvot](https://arxiv.org/abs/2610.21082) 评估真实科研中的关键决策。后续实验应独立评价结论依据、适用范围和重复运行稳定性。
