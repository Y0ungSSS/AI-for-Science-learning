## 一眼看懂：问题在哪里？

```text
AI Scientist 怎样才算可靠地做科学？
│
├─ Q1 科学构想：提出的想法新、对、值得做吗？
├─ Q2 研究控制：什么时候继续、回退、换方法或改目标？
├─ Q3 故障诊断：失败源于假设、实验、代码、数据还是评价？
├─ Q4 证据更新：实验结果真的改变了信念吗？
├─ Q5 研究状态：长程研究能记住什么，并证明结论来自哪里？
├─ Q6 科学执行：代码、仿真、软件产物何时构成科学证据？
├─ Q7 可信评测：怎样测科学发现而不是测答题与刷分？
├─ Q8 自我改进：跨轮经验何时真的提升方法，而非仅增长上下文？
└─ Q9 人机协作：哪些关键决策应自动、哪些应请求专家？
```

**问题与方法不要混淆**：`tree search`、`multi-agent`、`RAG`、`critic`、`memory` 是候选方法，不是天然的新科研问题。一个方法可以服务多个问题；一个问题也可能存在多条竞争方法路线。

**初步关注顺序（研究规划，不是论文结论）**：Q2／Q3／Q7 最适合从可执行 benchmark 和公开代码切入；Q4／Q5 可以作为后续延伸；Q6 可提供无需真实实验室的实验载体。状态标签：**拥挤**＝本样本中同类方案多；**活跃但证据缺口**＝已有直接工作，关键对照不足；**局部稀缺**＝在所检查语料中较少见，不等于全球没有论文。

## Q1. 科学构想怎样从“新颖”变成“值得执行”？

**问题结构**
- Q1.1 生成：文献重组是否会造成构想同质化？多样性是否改善下游结果？
- Q1.2 评价：`novelty ≠ soundness ≠ feasibility ≠ expected utility`，不能由单一分数代替。
- Q1.3 选择：pairwise / tournament / absolute score 哪种选择信号在何种条件下可靠？
- Q1.4 稳健性：judge、prompt、retrieval、reasoning budget 改变会不会使同一想法被判成不同等级？

**已见证据**：[Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y) 系统化生成／批评／排名／演化；[RND](https://arxiv.org/abs/2503.01508) 聚焦 novelty；[SoundnessBench](https://arxiv.org/abs/2605.30329) 聚焦 soundness；[Ideation-Execution Gap](https://arxiv.org/abs/2506.20803) 强调必须看执行后价值；[Old Ideas, Novel Problems](https://arxiv.org/abs/2610.02022) 报告 novelty 判定的设计敏感性。

**缺口判断**：idea-generation 的简单编排已**拥挤**；idea evaluator 的校准、可执行价值预测及跨设置稳健性仍**活跃但证据缺口**。对应[研究树 A1–A3、B1–B4、H7–H8](研究树.md#rt-b)。

**可测试的问题**：同一批 idea 和人工／可执行参照保持不变，只改变 judge prompt、模型、检索和预算，评价 verdict flip rate、ranking correlation、校准与 downstream utility。不要把 judge 分数当真值。

**2026-10-26 增量｜Q1.2/Q1.4：soundness judge 的顺序不变性与最小缺陷敏感度**：[Tampered ML](https://arxiv.org/abs/2610.32114) 以 1858 组原论文方案与单点方法学缺陷编辑组成配对测试；最佳报告准确率 77.9%，且交换呈现顺序显著改变判断，人工抽样仅估计 86% 的配对构造有效。相比一般 judge prompt 稳定性，**优先级提升为同一研究提案的最小故障检出与对称性**，并需单独报告人工标注有效率、误拒、顺序翻转。

**Codex E0b｜科研方法学配对缺陷审计**：选 25–40 条公开、可由统计脚本独立验证的实验提案，预注册唯一缺陷（train/test 泄漏、统计单位错、无效比较组、后验选择、超出证据的 claim）；对照原始/编辑、AB/BA 呈现、规则 oracle、LLM judge。固定模型与判断预算，记录 defect localization、pairwise accuracy、order-flip、judge abstention 和标注歧义。**否证**：若 judge 提升仅来自固定呈现位置、措辞线索或缺陷构造不合法，不认定 soundness 审查能力提升。

**2026-10-27 证据更新｜Q1：构想“新颖”与“预算可执行”必须分开验收**：[AlphaIdeaBench](https://arxiv.org/abs/2610.33644) 已将 100 个研究构想任务绑定 GPU/API/时间/标注预算，并将 novelty 拆成 problem/method/scenario/insight 四轴；8 harness 同 backbone 与 8 backbone 同 harness 的交叉比较显示 scaffold 与模型影响研究问题选择的方式不同。**饱和度修订**：预算约束 ideation 和 reviewer-aligned judge 已有直接前作，不再称“无人研究”；仍缺**真实执行成本对照、超预算惩罚的独立 oracle、judge 在边界缺陷/场景新颖性上的可靠校准**。论文用评审评论衍生分数作参照，94–97% 的 ±1 分一致率不能等同独立科学新颖性真值。后续沿用 E0b 的最小缺陷与顺序交换对照，在相同 idea 上增加预注册资源上限和真实脚本成本，比较“文本可行”与“执行可行”。

**2026-10-29 增量｜Q1 的 novelty gate 已有 claim-level 直接前作**：[ClaimNov](https://arxiv.org/abs/2610.36511) 将提案拆成贡献主张、按 claim 检索和判定既有覆盖，并以 temporal/混合新旧贡献构造反事实评价。**饱和度修订**：不能再把“拆解 idea 为 claim、逐条找前作”当作未研究机制；真正未决的是跨领域 prior-art 检索池不完整、claim 提取错误、时间泄漏与执行价值是否造成系统性误拒。对现有 E0b 增加“单一旧 claim 混入新提案”和“移除/加入真实前作”的成对反事实；报告 false rejection、正确 prior-art attribution、总检索/判定成本。若新方法的增益仅来自更大的检索池或更强模型，则不承认机制独立贡献。

## Q2. 研究何时应该换路线，而不只是继续修改？

**问题结构**
- Q2.1 **Local refinement**：A→A′→A″ 是否只在局部徘徊？
- Q2.2 **Rollback**：分支退回是否优于贪心改写？
- Q2.3 **Strategy switching**：是修实现、改实验设计，还是放弃整个 method family？
- Q2.4 **Goal change**：现有 objective 是否本身错了？
- Q2.5 **Stopping / resource allocation**：何时继续试、何时验证、何时停止？

**已见证据**：[The AI Scientist-v2](https://arxiv.org/abs/2504.08066) 有实验树；[ERA](https://www.nature.com/articles/s41586-026-10658-6) 有可评分程序搜索；[SciNav](https://arxiv.org/abs/2603.20256) 用相对比较选 frontier；[PrimeScientist](https://arxiv.org/abs/2609.17846) 涉及预算分配；[SAGA](https://arxiv.org/abs/2512.21782) 改 objective。[Runtime Agent Coordination](https://arxiv.org/abs/2610.00980) 的“切换执行者／能力”不同于 scientific method-family pivot。

**缺口判断**：搜索方案很多，通用的“**诊断原因 → 选择修改层级 → 在固定预算下验证转向收益**”仍局部稀缺。**Backtrack ≠ pivot ≠ change objective**。对应[研究树 C1–C6、D3、H8](研究树.md#rt-c)。

**Codex 实验候选 E1｜固定预算的跨层决策**（优先）
- **任务**：建立可执行的科学代码／模拟小任务集，分别植入实现缺陷、方法族不适配、目标／评分指标错配；让 agent 决定 repair、refine、rollback、pivot 或 stop。
- **对照**：always-refine、固定 tree search、规则路由、oracle 故障层级；保证模型、工具、总 token / 执行调用 / wall time 尽可能一致。
- **记录**：每步观察、选项、选择原因、失败轨迹、切换成本、独立测试集上的成功率和 total cost。
- **能推翻假设的结果**：复杂策略在同预算下不优于简单重试／回退；或收益主要来自额外样本而非决策。
- **前置关口**：先确认任务里确实需要跨层转向，且不同故障类型具可区分的 oracle label；不直接投入长时间训练。
- **2026-10-12 证据与实验补充**：[JANUS](https://arxiv.org/abs/2610.13194) 将执行前预测用于分支排序，但其预测值校准和额外判断成本仍需独立核验。Codex 可固定候选池与执行预算，比较随机选择、执行后贪心、静态预测、在线更新预测；测 predicted-vs-actual gain 的校准、每单位总成本的最终收益与错误剪枝率。

**2026-10-21 证据重审｜Q2：从经验性 pivot 转向诊断性 pivot**

[LLM-IDEA](https://arxiv.org/abs/2610.11253) 将平台期分为 agent 能力限制、可通过现有设计解决的不可辨别、当前观测协议耗尽；[SHELDON](https://arxiv.org/abs/2610.18025) 将假设与观测空间分开探索；[Possibilistic Reasoning](https://arxiv.org/abs/2610.11289) 给条件化统计有效性/停止目标；[Station](https://arxiv.org/abs/2610.08927) 研究无中间 reward 时的持续探索。这些工作说明 **pivot/停止不是无人研究的空白**，真正缺口在决策路由和证据条件的独立验证。

**Codex E1b｜三类平台期与策略转向**：用受控 ODE/线性逆问题构造 A 低模型能力、B 当前设计可解决不可识别、C 观测协议内完全不可识别；固定 20–40 次仿真查询预算，比较随机/局部重试、规则诊断、灵敏度矩阵诊断、oracle 路由。测错误停止率、错误转向率、科学机制 held-out 恢复率、单位正确结论所需查询；**若诊断带来的收益仅来自额外观测或特定 prompt，则否定“诊断器机制独立有效”**。与 [Learning to Outgrow a Theory](https://arxiv.org/abs/2610.07627) 的结构编辑对照，禁止假设测试集候选空间恒包含真解。

**2026-10-24 增量｜Q2 的饱和度与成本归因**：[ADAPT for Science](https://arxiv.org/abs/2610.30851) 把“从哪里开始”与“如何搜索”拆成可消融的两个优化决策，在 8 个未见引力波探测器拓扑上有同科学评测预算的优势；[SpecEvo](https://arxiv.org/abs/2610.28706) 以轨迹停滞触发昂贵模型 checkpoint；[AgenticEvolve](https://arxiv.org/abs/2610.31326) 对照 No-analysis 隔离正式评测之间自定实验的收益。**修订**：科学优化器自演化/大小模型路由已属活跃机制，Q2 的缺口应更精确地限定为**故障原因驱动的跨方法族 pivot/stop，以及所有资源成本计入后的收益**。上述工作大多改搜索策略，不等于改变科学研究问题。Codex E1/E1b 增加双成本轴：固定正式 evaluator calls 与固定总 token+本地实验 CPU 时间分别比较，防止将额外本地探索误算为免费增益。

**2026-10-27 证据更新｜Q2：跨方法族 pivot 已有正面实证，关键是单独识别切换策略**：[LegoSR](https://arxiv.org/abs/2610.33465) 用共享 Equation IR/统一评分将 SINDy、PySR、DLGA-PDE 等七种方法纳入一个可切换 solver 池，并在同模型/工具/预算下优于 generic agent；它比 [LLM-IDEA](https://arxiv.org/abs/2610.11253) 的平台期诊断更接近实际跨科学求解方法的选择。[Organon](https://arxiv.org/abs/2610.33046) 可在线修改自身搜索和诊断程序，但缺单机制消融。**饱和度修订**：方程发现中的 method-family switching 已有直接研究，Q2 不应再宣称方法切换完全空白；开放问题是区分 solver knowledge、统一接口、反馈、策略切换、总计算预算各自贡献，以及跨不同科学任务是否可迁移。

**Codex E1c｜低资源跨求解器路由**：用 PySINDy、PySR（或轻量符号回归）、稀疏线性/多项式基线构造 12–20 个可执行 ODE/方程发现任务（含噪声、错误候选项库、不同稀疏度）；固定 train/test、CPU wall time、总 solver calls，比较单最佳 solver、规则路由、随机切换、反馈触发切换和 oracle 最优路由。必须单列统一评分/solver cards/历史经验开关；测 held-out 轨迹误差、结构恢复、错误切换、成本。**否证**：若切换收益由多跑 solver 或统一接口造成，或简单规则路由同样有效，不认定 Agent 学到了独立的科研策略控制机制。


**2026-10-28 增量｜Q2：等待自恢复、预测性执行与主动干预的成本边界**：[ReInBench](https://arxiv.org/abs/2610.36471) 已直接研究 Web/GUI Agent 的“现在介入 vs 等待自恢复”，故不能将 intervention timing 作为空白；[MLE-World](https://arxiv.org/abs/2610.37175) 已研究预测执行终态+置信门控，且需要昂贵预训练。**开放边界**缩小为：在科学代码/仿真任务中，诊断实验、直接修复、等待、切换方法分别有什么独立净收益？须把模型调用、诊断执行、等待成本和真实实验时间一起计算。沿用 E1/E1c，不将世界模型训练作为个人低资源默认前提。


**2026-10-29 增量｜Q2 跨求解器路由的创新性边界进一步收紧**：[NextEval](https://arxiv.org/abs/2610.36553) 已在 DFO 上实现 LLM 选择数值方法、参数与评价预算，使用共享历史和固定工具的 benchmark；结合 [LegoSR](https://arxiv.org/abs/2610.33465)，scientific solver routing 已有至少两类直接任务前作。**E1c 补充控制**：在保持候选方法、数值工具和历史记录完全相同的条件下，比较确定性规则控制器、随机/贪心控制器、LLM 控制器、oracle；同时固定 evaluator calls 和**总** token+CPU wall time 两条成本轴，并按未见方程家族留出。NextEval 的 whole-system 改善没有完成 LLM/工具/路由的独立归因（论文将机制消融列为计划），因此这一可证伪的归因缺口仍有价值；但“增加一个 Agent 选 solver”本身不构成创新。

## Q3. Agent 能否正确定位失败并做定向修复？

**问题结构**
- Q3.1 失败来自 hypothesis、experiment design、implementation、data、metric、analysis、evaluator 哪一层？
- Q3.2 观测不足时，能否主动设计**区分不同故障解释的诊断实验**？
- Q3.3 多层同时故障如何处理？“工具调用成功但字段缺失”如何发现？
- Q3.4 诊断正确是否真的提高修复效率，而非只生成合理解释？

**已见证据**：[FIRE-Bench](https://arxiv.org/abs/2602.02905) 支持事后阶段错误分析；[SAGE](https://arxiv.org/abs/2606.31478) 提出运行时归因和干预路由；[Silent Failures](https://arxiv.org/abs/2609.26836) 指出工具链边界的信息损失；[ASCEND](https://arxiv.org/abs/2609.32868) 提供 HPC 故障恢复案例。

**缺口判断**：并非空白，属于**活跃但证据缺口**；关键是跨层组合故障的真值和诊断→修复的因果收益。对应[研究树 F1–F2、C5、G3](研究树.md#rt-f)。

**Codex 实验候选 E2｜已知故障注入与归因**
- **任务**：用可复现的科学数据分析脚本注入不同层错误（字段丢失、单位换算、代码逻辑、数据泄漏、无效指标），保留故障注入 manifest 作为 oracle。
- **对照**：free-form reflection、单层 rule-based diagnostic、多假设归因、oracle 归因；保留独立未见故障组合。
- **指标**：故障层定位准确率、诊断实验数量、targeted-repair 成功率、误修率、成本；定位正确≠修复正确。
- **能推翻假设的结果**：定位标签看似准确，但修复成功率／成本未改善。

**2026-10-21 证据重审｜Q3：不要只诊断代码错，还要诊断“目标/指标错”**

[Coupled Harness–Model Evolution](https://arxiv.org/abs/2610.17740) 将“没有所需工具”和“有工具却未调用”分离；[SwarmRSI](https://arxiv.org/abs/2610.20431) 区分假设缺陷与组件缺陷并复用局部正结果。[Same Simulation, Different Evidence](https://arxiv.org/abs/2610.26836) 提供**结果计算正确而读取权威来源失败**的反证，因此 Q3 层级需要显式包含 evidence retrieval / authority selection，而非将所有答错归入推理、仿真或代码。后续关注指标代理失真与跨层复合故障，但仍缺少可独立核实的通用错误目标诊断机制。

**2026-10-23 增量证据｜Q3 失败归因与目标错配**：[DAGLoop](https://arxiv.org/abs/2610.25089) 将设计决策、必要前提与消融测试组成 DAG，避免拆掉前提后错误归因；[Aptamers](https://arxiv.org/abs/2610.24806) 的实体 counter-screen 发现“结合强但非特异”的代理指标陷阱并调整后续策略。**修订**：Q3.1/Q3.2 不只需知道哪层失败，还需验证某设计在**其依赖条件成立时**是否真有预期效果；metric/assay artifact 是独立故障层。原始研究的设计依赖图可能不完整，湿实验的不同轮次 harness 变化也不能归因于单个 LLM 策略。

**Codex E2b（低资源）**：在 3–5 个可执行模拟/ML 小任务预先设置 A 依赖 B、A×B 交互和错误代理评分，比较普通逐项 ablation、依赖保持 ablation、oracle 因果结构。预注册每个设计的预期效应与实验条件，固定候选数和运行次数；指标为错误贡献归因率、真实目标 held-out 改善、额外计算成本。**否证**：依赖保持策略不能比简单联合消融减少错误归因，或仅改善代理分数。


**2026-10-28 增量｜Q3：诊断正确不等于应该立即干预**：[ReInBench](https://arxiv.org/abs/2610.36471) 在 1403 个通用 Agent 错误事件中观察到 725 次自恢复，直接挑战“出现错误→马上修复”的默认控制逻辑；但它的 self-recovery 分类 F1 不证明科学修复净收益，也没有科学故障层级真值。Q3 的优先验证点调整为**同一故障证据下等待、诊断、修复三种动作的反事实成本/成功率**。

**Codex E2c｜科学故障的等待-诊断-修复对照（低资源）**：在 20–30 个 Python/ODE/数据分析任务预先植入可独立验证的故障（随机暂态、工具字段延迟、代码 bug、错误指标），为每项设置真实可恢复/不可恢复状态与最小修复动作；固定总执行调用、token、CPU 时间，比较 always-retry、always-repair、规则等待门控、简单不确定性门控、oracle 动作。记录错误修复、过早介入、错误等待、最终 held-out 科学正确性与全成本。**否证**：如果规则基线接近 oracle，或所谓收益来自多给重试/更长预算，不认定新型科研决策机制成立。先查 ReInBench/SAGE 的干预时机和恢复定义，避免直接复刻。


## Q4. 实验反馈是否真正更新科学信念？

**问题结构**
- Q4.1 保存结果与显式更新 belief（预测、不确定性、支持／反证）有何不同？
- Q4.2 遇到与先验冲突的数据，是否承认错、降低置信度？
- Q4.3 能否选择最能排除 competing mechanisms 的辨别实验？
- Q4.4 拟合外部规律是否代表发现内在 mechanism？

**已见证据**：[Robin](https://www.nature.com/articles/s41586-026-10652-y) 形成实验反馈；[BayesEvolve](https://arxiv.org/abs/2606.30335) 用显式信念做优化决策；[WhatWorkedBench](https://arxiv.org/abs/2609.27490) 测实验后预测；[MechBench](https://arxiv.org/abs/2609.35515) 区分现象规律和机制恢复。

**缺口判断**：预测性 belief 已有机制雏形，但对真实科学任务的多轮校准与机制鉴别仍**局部稀缺**。对应[研究树 F3、E4–E5、H7](研究树.md#rt-f)。

**2026-10-18 新证据 → Q4/Q7 接口**：[Evaluating Inquiry Learning](https://arxiv.org/abs/2610.21604) 在有限数学交互环境中同时观察变量选择、推理和假设细化；[Autonomous Science Bench](https://arxiv.org/abs/2610.18449) 则把“测到高价值设计（discovery gate）”与“对未见设计的预测排序（learning gate）”分开。**缺口修订**：不应仅以找到最佳配置说明 agent 真正更新了可泛化的机制信念；需要独立留出集检验实验后预测，以及排除提示式 scaffolding 和额外测量预算的贡献。该结论仅限两篇的受控任务，尚非开放科学通用定理。

**Codex 实验候选 E3｜多假设模拟**
- 用可生成独立观测的简化模拟器，设置多种生成机制；每轮强制 agent **先记录下轮预测和置信度**，再看到结果。
- 比较无状态文本反思、结构化证据表、显式概率 belief；控制实验次数和模型预算。
- 评价 held-out prediction、Brier score／适用时的 log-loss、假设淘汰质量、区分实验效率；避免让模拟器真值进入 prompt。

**2026-10-21 证据重审｜Q4：机制、目标律和证据响应应分开测**

[OptScientist](https://arxiv.org/abs/2610.28562) 恢复的是能够解释最优行为的**隐含目标/约束**，不是单纯拟合动力学；但 inverse optimization / inverse optimal control 已有成熟前作，且行为偏好/最优排序吻合不保证目标唯一可识别。[MechHypoBench](https://arxiv.org/abs/2610.05197) 从观测到开放机制假设，利用隐藏条件的后果检测。[Are We Measuring Scientific Intelligence?](https://arxiv.org/abs/2610.04915) 显示正确答案可能不依赖当轮科学证据。Q4 因此应分别测：① 已给证据的因果使用；② held-out 预测；③ 机制/目标可识别性；④ 数据冲突时的置信度校准。

**轻量可证伪延伸**：用二次规划/带约束线性规划生成最优行为数据，设置两组能产生相同排序但不同目标表达的 world；比较拟合预测、目标式回归、oracle 同值类判定。对不可识别世界要求 agent 输出“等价解释集合”而非自信声称唯一真实律。指标包括选择集外预测、区分实验有效率和过度确定率。与已有逆优化方法作为必要 baseline，暂不立新 Research Problem。

**2026-10-23 关键反证｜Q4 的“反馈被使用”必须先于“反馈有收益”检验**：[When Does Feedback Help?](https://arxiv.org/abs/2610.27632) 在合成电压钳环境中，5 个策略 1200 次 rollout 全部重复固定协议，mask 电流不改变行动；另一任务的策略确实用反馈，但与简单 Bayesian/阈值策略相当。[PEARL](https://www.biorxiv.org/content/10.64898/2026.10.20.760214v1) 和 [Aptamers](https://arxiv.org/abs/2610.24806) 为实体实验中主动获取信息/修改设计提供实例，但不足以替代受控反馈消融。**缺口更新**：真实闭环中的观测依赖与策略质量是两个独立指标，Q4.1/Q4.2 的证据强度上调，通用 belief 校准仍未解决。

**优先 Codex E3b｜反馈因果依赖审计（低资源）**：在小型 ODE/黑盒模拟器预制不同观测对应不同最优实验的 paired worlds；同一决策状态对照 (a) 真观测、(b) mask、(c) 随机置换、(d) 与真值冲突的反事实观测。固定模型、先验、历史、总查询/时间预算，先记录下轮实验选择和概率预测，再看结果。分别报告 **action sensitivity / conditional information gain、held-out prediction/Brier、最优实验质量、误转向率与成本**。**否证**：模型在观测被替换后决策不变却获得高最终分数，说明分数不能支持“反馈驱动”；决策敏感但性能不优于规则/Bayesian baseline，也不能宣称策略更优。

**2026-10-24 增量｜Q4 显式科学信念的最低标准**：[Bayesian Model Discovery](https://arxiv.org/abs/2610.25747) 用模型族 evidence、参数后验和联合 expected information gain 将“新实验→模型后验→下次实验”数值闭合，补强 Q4.2/Q4.3；相较纯 LLM 反思，能检查每一步预测分布，但其后验只在当前有限候选池内有效。[Null Controls](https://arxiv.org/abs/2610.22445) 进一步提醒：验收测试通过不意味着模型保留科学上有意义的可观测后果。

**Codex E3c｜错设模型池的 belief-update 反证**：构造 2–3 个低维 ODE/符号回归环境，设置 (A) 真模型在候选池、(B) 真模型不在候选池但有近似候选、(C) 观测不可辨别。固定实验预算，比较文本反思、Bayesian family posterior+EIG、随机设计、oracle。各组加入真实反馈/屏蔽/置换；测 held-out 预测、log score、置信区间覆盖、posterior 过度确定率、有效区分实验率。**可证伪**：若 B/C 中模型在错设或不可辨别条件下仍高置信度错误，而 agent 不请求扩张模型族/报告不可判定，就不能声称科学 belief 已可靠更新。与现有 E3b 反馈依赖审计互补，不重复立项。

**2026-10-26 增量｜Q4：观察到证据、解释证据、按证据改变动作仍是三个关口**：[DMAIC-Bench](https://arxiv.org/abs/2610.32305) 的配对 GO/NO-GO 测试显示模型常报告正确统计诊断却继续执行不允许的下游分析（作者报告 13 模型均值 GO 92%、NO-GO 19%）；这是 [When Does Feedback Help?](https://arxiv.org/abs/2610.27632) 的反馈屏蔽反例之后的**行动门槛**证据。[Principia](https://arxiv.org/abs/2610.32195) 提供假设→语言原则→新观测的循环，但因果措辞不等于可识别科学机制；[Adaptive Control](https://arxiv.org/abs/2610.32370) 的真实仪器调参则仍受人工监督。**缺口修订**：belief update 不仅测 belief text 变化，还要测预注册反事实条件下的**下一步行动合法性和 held-out 机制预测**。

**Codex E3d｜配对 GO/NO-GO 科学行动门槛**：用 20–40 个小型 Python 统计/ODE 分析流程，预先定义前置假设检验、可执行下一步和停止/换实验的 oracle；构造同任务节点的 GO 与 NO-GO 反事实观测。比较无约束 Agent、仅反思、确定性 action gate、LLM gate、二者组合，保持同模型/同执行预算。分别报告诊断正确率、禁止动作执行率、正确停机/升级率、误停率、独立后果预测及额外成本。**否证**：如果所有 NO-GO 一律停机即可取得高分，或正确率来自规则提前泄露 oracle，而非观测条件下的决策，不能宣称科学信念驱动了行动。

## Q5. 长期研究怎样可恢复、可审计、不过度依赖上下文？

**问题结构**
- Q5.1 episodic memory、skills、研究状态、evidence provenance 是否混为一谈？
- Q5.2 跨轮 failed attempts、决策理由、版本及负结果如何可靠保存？
- Q5.3 从最终 claim 能否追溯数据、配置、代码、实验和证据？
- Q5.4 删除／篡改一段 provenance，系统是否发现结论已不可核证？

**已见证据**：[EvoScientist](https://arxiv.org/abs/2603.08127)、[XScientist](https://arxiv.org/abs/2607.12301)、[Arbor](https://arxiv.org/abs/2606.11926)、[Data-to-Paper](https://arxiv.org/abs/2404.17605)、[OpenDiscoveryTrace](https://arxiv.org/abs/2609.09203)。

**缺口判断**：状态表示**活跃**，完整 claim 核证仍局部稀缺。可以用小项目做 provenance corruption / recovery 实验，无需真实实验室。对应[研究树 G1–G3、D1、H6](研究树.md#rt-g)。

**2026-10-21 证据重审｜Q5：长时记忆的价值不是记录量，而是来源真实性与条件化保留**

[Épi](https://arxiv.org/abs/2610.24944) 将多会话持久研究状态、分支与固定验证器结合；[DrugHarness](https://arxiv.org/abs/2610.23791) 以 applicability conditions 和 source review 筛选可复用技能；[Same Simulation, Different Evidence](https://arxiv.org/abs/2610.26836) 说明**仿真正确不保证引用到权威输出**。将 Q5.3/Q5.4 的 provenance 分成“能追溯”和“决策确实用对来源”两层，二者不是同义词。

**Codex E5｜证据替代消融（优先）**：固定同一批科学计算的正确输出，提供 (a) 完整内联权威日志，(b) 文件检索，(c) 索引检索+显式权威指针，(d) 结构化 claim→source 链；注入名称相近的中间/旧版/不同精度输出，控制相同模型、问题与执行预算。记录 oracle numerical correctness、source selection accuracy、claim-level correctness、false confidence 和额外 token/time；**如果加入 provenance 仅改善可读性、不改善正确引用，不能宣称提高了科研可信度**。此实验是 [Same Simulation](https://arxiv.org/abs/2610.26836) 的独立扩展，不声称首次发现该机制。

**2026-10-24 增量｜Q5 的证据来源从“存在”提升到“支持”**：[Real PMIDs, Wrong Papers](https://arxiv.org/abs/2610.29812) 在固定模型与 PubMed harness 消融中，发现 closed-book 生成的 335 个 PMID 中 327 个真实存在，但跨模型审查仅 3 个与对应 claim 相关。该证据支持 Q5/G3 的四级验收：**来源存在→确实是本次引用的文献/输出→内容相关→足以支持该主张**。与 [Same Simulation, Different Evidence](https://arxiv.org/abs/2610.26836) 的计算输出替代是同一更广义来源选择问题，**不新增研究问题**。在已有 Codex E5 中注入“真实但不相关 PMID / 旧版数值日志”并设独立人工或规则 oracle；报告 source-existence accuracy 与 claim-support accuracy 的差距。注意原文相关性由跨模型 LLM judge 评估，非绝对真值。

**2026-10-27 证据更新｜Q5：正确记录仍可能不具备当前科学决策的使用资格**：[SciValidityBench](https://arxiv.org/abs/2610.34767) 将 G2/G3 的来源真实性、版本与完整性推进到**use admissibility**：同一个真实 p 值，若分析终点在看结果后才选出，不能按预注册验证来使用；同名测量可能跨版本不可比，缺失值可能是未运行/失败/删失而不是零。64 个可执行 TaskSpec 的状态编译优于通用事件图 9.2–18.8 个百分点（作者报告），但规则 oracle 与编译器已编码规范，不代表开放科研真值。**缺口修订**：provenance 从“找到正确来源→相关→支持主张”扩展为“**在当前预注册/停止/测量/权限状态下允许怎样使用**”。这与 Q4 的 GO/NO-GO 动作和 Q7 的有效性协议交叉，但仍属于 Q5，不新增 Q10。

**Codex E5b｜科学证据使用资格的反事实审计（优先）**：构造 24–40 对合成研究日志，固定观测值、来源与结论请求，只改变计划锁定时间、是否多重检验、停止规则、测量定义版本、缺失原因；规则 oracle 预注册合法动作（confirm/explore/retest/abstain）。比较完整事件日志、BM25/事件图、手工规则状态表、LLM 生成状态摘要、编译状态表；固定模型和 token，另算编译成本。测 factual retrieval、source support、**use-valid decision**、反事实翻转正确率、false confirm 与错误拒绝。**否证**：若模型只是读取编译器直接泄露的答案，或换领域/多故障后优势消失，不能把状态编译当成真正的科研信念更新。


**2026-10-28 增量｜Q5：来源链必须区分重复转述与独立验证**：[Replication or Corroboration?](https://arxiv.org/abs/2610.36151) 在多 Agent debate 形式化证明：若输入不携带可区分的证据根，judge 无法同时忽略复制证据、认可真正独立的新证据。相较原有 G3 的来源记录，增加**evidence root identity / shared ancestry** 作为科学 claim 的必要审计维度；但该结果假设 root partition 可知，真实科学论文共用数据/预印本/实验记录时不一定可判。Codex 可在 E5b 的相同 claim 中复制/改写引用、加入真正独立实验，测 judge verdict 是否受重复票数影响；先用确定性去重和来源 DAG 作强基线，不另立 Research Problem。


## Q6. “科学任务运行成功”何时能够支持真实科学结论？

**问题结构**
- Q6.1 coding、reproduction、research extension、new method search 是不同能力层级。
- Q6.2 simulation 要同时测数值正确性、物理有效性、效率与可识别性。
- Q6.3 科学软件 GUI artifact 正确，是否意味着解释和 claim 正确？
- Q6.4 实体实验中的人类干预与噪声如何进入结论？

**已见证据**：[ScienceAgentBench](https://arxiv.org/abs/2410.05080)、[RExBench](https://arxiv.org/abs/2506.22598)、[ERA](https://www.nature.com/articles/s41586-026-10658-6)、[GPUPhysBench](https://arxiv.org/abs/2609.35639)、[OSWorld-Science](https://arxiv.org/abs/2609.39903)、[Robin](https://www.nature.com/articles/s41586-026-10652-y)。

**缺口判断**：科学编码／可执行基准已**活跃**；从 executable artifact 到 claim verification 的桥梁仍不完整。适合作为 Q2–Q5 的实验环境，而非仅靠增加一个 coding agent 创新。对应[研究树 E1–E5、H1–H5](研究树.md#rt-e)。

**2026-10-18 新证据 → Q6/Q7 接口**：[Into the Unknown](https://arxiv.org/abs/2610.19159) 发现 AI 生成的开放科研 follow-up 可能声称没有实际执行的实验；[Structure Before Intelligence](https://arxiv.org/abs/2610.19507) 用版本化 DAG、验证器和 release gate 管控无效科学产物。**缺口修订**：可执行产物“存在”还不够，必须有从 claim 到数据/代码/运行记录的核对；确定性 gate 应作为 LLM 审查的强基线，同时测误拒/误放，不把局部零误放写成全领域保证。

**2026-10-21 证据重审｜Q6：运行环境与研究结论之间还有两个独立障碍**

[PhysCodeGym](https://arxiv.org/abs/2610.17288) 通过反事实物理干预指出表面逼真但物理机制错误的程序；[Self-Building Labs](https://arxiv.org/abs/2610.23826) 提出了为目标实验自动搭建数字孪生与机器人技能的执行能力构建。后者是 E5 的**执行环境自构建**子方向，而非新一级 Research Problem，涉及硬件安全、校准、人工参与和成本。软件/设备搭好、实验执行成功和科学主张得到验证必须分别记录。

## Q7. 怎样评测“科学发现”，而不是模型背题、刷指标或迎合评委？

**问题结构**
- Q7.1 **测量对象**：knowledge QA／component／reproduction／extension／rediscovery／open-ended discovery 不能互换总分。
- Q7.2 **可见信息**：目标论文、方法和结果是否隐藏？web 是否开放？
- Q7.3 **独立真值**：任务可执行吗，claim 有外部验证吗，机制识别有探针吗？
- Q7.4 **评判稳定性**：judge／prompt／retrieval／budget 改变是否翻转结论？
- Q7.5 **协议公平**：相同模型、工具、搜索预算、硬件和成本？
- Q7.6 **防污染与反作弊**：静态题、动态题、轨迹和可见反馈各有什么攻击面？

**已见证据**：[AstaBench](https://arxiv.org/abs/2510.21652) 提供工具／成本控制；[FIRE-Bench](https://arxiv.org/abs/2602.02905) 使用已发表研究的外部参照做 rediscovery；[RExBench](https://arxiv.org/abs/2506.22598) 把 research extension 单列；[SoundnessBench](https://arxiv.org/abs/2605.30329)、[MechBench](https://arxiv.org/abs/2609.35515)、[Old Ideas, Novel Problems](https://arxiv.org/abs/2610.02022) 覆盖不同评测偏差。

**缺口判断**：benchmark 数量不稀少；同时满足开放性、执行、独立验证、防泄漏和公平成本的协议仍**证据缺口**。对应[研究树 H1–H8](研究树.md#rt-h)。

**2026-10-18 评测边界更新（见[研究树 H7](研究树.md#rt-h)）**

- **Discovery ≠ Learning**：[Autonomous Science Bench](https://arxiv.org/abs/2610.18449) 让实验选择与未见设计预测通过两个独立关口；补强 Q7.1/Q7.3，不能用单一 campaign 成功率替代泛化能力。
- **完成科研稿 ≠ 证据完整**：[Into the Unknown](https://arxiv.org/abs/2610.19159) 的开放 follow-up rubric 与 integrity check 把 paper–execution 不一致显式暴露；补强 Q7.3/Q7.6。
- **验证通过 ≠ 推理改善**：[ClaimScope](https://arxiv.org/abs/2610.21581) 的 schema-only 后处理匹配验证器带来的安全完成提升；[Structure Before Intelligence](https://arxiv.org/abs/2610.19507) 在受控发布任务中未测出 LLM 的独立收益。应单列 formatting/schema repair、确定性 validator、LLM review 三种贡献。两项研究任务范围较窄，不据此否定所有 LLM 审查。

**优先交给 Codex 的低资源实验 E4b｜科研主张的分级发布核验**
- **任务**：选公开科学分析脚本/小型 ODE 模拟，预制正确产物和含数据版本过期、单位/数值错误、遗漏必要步骤、结论超出证据范围的成对产物，保留独立 oracle。
- **因子对照**：① 不验证；② 仅 schema/格式修复；③ 确定性测试+provenance gate；④ LLM 评审；⑤ ③+④。固定输入、模型、token、执行次数和可见证据，另外记录验证器成本。
- **指标**：false release、false rejection、claim-level accuracy、证据链覆盖、成本；分开评价局部通过和科学结论闭合。用未见故障组合验迁移。
- **可证伪点**：若简单 schema/rule-based gate 已与 LLM 审查同等有效，不能把增加 critic 当新机制；若验证器误拒显著，不能把“零放行”当整体最优。

**Codex 实验候选 E4｜协议变量消融**
- 固定同一批可执行任务、agent 和总预算，仅依次改变：judge prompt、source-paper 可见性、是否评轨迹、是否启用独立检查。
- 先定义外部可复核的正确性（代码测试／模拟已知机制），再观察 benchmark 排名翻转与 shortcut 率。
- 指标：rank stability、false-pass、false-reject、成本、跨任务泛化。若改变协议会轻易改变榜单，则“某系统更会科研”的结论需要限定协议。

**2026-10-21 证据重审｜Q7：新评测应防止“学会答案但没用数据”**

[AutoSciBench](https://arxiv.org/abs/2610.05140) 提供随 agent 失败轨迹演化的 benchmark 配方，但困难度增加不等于真值和真实性提高；[Are We Measuring Scientific Intelligence?](https://arxiv.org/abs/2610.04915) 直接以保留/撤除/反转证据检测数据依赖；[DrugTargetWorld](https://arxiv.org/abs/2610.09558) 通过隐藏模拟因果结构构造可评分真值；[RSI-Forge](https://arxiv.org/abs/2610.09426) 把论文复现映射成可执行环境并承认 shortcut/reproduction fidelity 仍成问题。**更新优先级**：真值可靠与 claim–evidence 因果连接优先于更多题和更高难度。

Codex 协议扩展：对于每个 benchmark 条目同时提供原证据、经预注册统计检验的证据撤除/反转、以及确定性和 LLM 评分；先测 data-responsiveness，再测单次任务分。若模型在反向证据条件下仍输出旧答案而总分不变，说明该分数不是稳健的科学证据理解指标。

**2026-10-23 评测协议更新｜Q7：分开检验 verifier 正确、科学推理与工程分数**：[VeriEvolve](https://arxiv.org/abs/2610.29005) 先合成并校准可执行 evaluator、每轮冻结、轮次间以反事实终态修订；其外部 held-out 一致性 113/122，说明自建题上满分不等于独立可靠。[Agent4Sci](https://arxiv.org/abs/2610.28763) 的 20 个科学 ML benchmark 表明，模型改进可主要来自通用工程技巧而非新科学 insight；插件使分数进一步提高，也需拆分 model/scaffold 与资源贡献。[Distributed Biological Reasoning](https://www.biorxiv.org/content/10.64898/2026.10.15.759436v1) 的隐藏原论文、held-out 扰动和专家盲评值得借鉴，但多 agent 与总成本混杂。**Q7.3/Q7.5 优先级上调**：外部真值校准 + 科学新颖性分类 + 同成本审计，不能用同一个分数代替。

**Codex E4c（协议增补，不另立问题）**：固定 20–30 个可执行科学分析故障，先独立标注正确状态和错误主张；用同一数据比较自动生成 verifier、人工规则 verifier、冻结后经反事实修订的 verifier，统计 held-out false-pass/false-reject 与版本漂移。另将最终改进标注为修 bug/调超参/改模型结构/提出新科学假设，盲评其证据支持；所有 agent 比较使用相同模型、数据划分、执行次数和总 token/时间。

**2026-10-24 增量｜Q7：科研诚信是过程指标，不是仅看最终报告**：[RIDAR](https://arxiv.org/abs/2610.31372) 将 14 类科研诚信违例与证据跨度绑定，配对轨迹中 runtime 监测使剩余违例平均减少 36.8%（作者报告）；它补强 H7/G3 的**在线科研过程审计**，但 60 条 gold 轨迹主要是数学/ML，检测器本身仍可能误报。[Null Controls](https://arxiv.org/abs/2610.22445) 指出无信息的零映射也可通过表面 closure；[Auditing the Product, Not the Recursion](https://arxiv.org/abs/2610.27610) 指出 RSI 产品评价和改进程序的因果评价需要不同协议。**优先级修订**：过程 integrity、可验证 claim 后果、独立真值和完整多次运行应优先于单一成功率；不因为 RIV 数量多就假定每项均有人工证实。

**Codex E4c｜低成本科研诚信运行时门控**：在小型科学代码任务中植入已知违例（引用错误、虚构执行、选择性报告、数据泄漏、跳过必需检验），对照无监测、只做 post-hoc、规则 runtime gate、LLM runtime monitor、两者组合；固定模型与任务、独立 oracle 标注，测真实违例召回/误报、错误放行、任务完成率、干预延迟和 token/时间成本。**否证**：若监测只是把违规报告改写得更像合规、未减少独立 oracle 认定的违规，或误拒正常实验显著上升，则不能声称科研可信度改善。

**2026-10-25 证据修订｜Q7：主张语义、验证器测量、反复升级的统计风险是三个不同关口**

- **主张语义可执行**：[ARATest](https://arxiv.org/abs/2610.30495) 将科研 claim 映射为固定的 typed property（范围/比较对象/统计单位/数值策略），让原报告和新运行使用同一测试；但仅 54/243 个 claim 成功完整绑定（22.2%），所以 **claim-to-property fidelity 和可覆盖比例**必须与检测到的错误数分别报告。对比既有 [ClaimScope](https://arxiv.org/abs/2610.21581) 的见证检查及 [Structure Before Intelligence](https://arxiv.org/abs/2610.19507) 的 release gate：执行式验证已有直接前作，新缺口是范围忠实和跨实验重用。
- **验证器标签并非客观事实**：[What the Trace Shows and What the Label Says](https://arxiv.org/abs/2610.30491) 在算术工具故障任务中发现 visible re-verification detector 会漏判 silent tool-output override，人工复核仅 67/81 verification 标签一致；补强 [RIDAR](https://arxiv.org/abs/2610.31372) 的 detector false-positive/false-negative 独立审计要求。该论文并非科研实验，因此是支持性负证据。
- **持续有效性 ≠ 单轮通过**：[Lifetime-valid decisions](https://arxiv.org/abs/2610.30562) 对不断更新的 AI 统计分析器提出新 null 情景验证和 lifetime risk 分配，给出**覆盖情景内**的 Type I error 控制；[CMAS](https://arxiv.org/abs/2610.31436) 的 paired shadow replay 与每次晋升误判率仅为经验控制，不能等同全生命周期保证。Q7.5/Q7.6 的优先级上调至“统计错误在自适应迭代中累积”的独立协议问题，但仍归属现有 Q7，不新增 Research Problem。

**Codex E4d｜主张可执行契约与评审器一致性（低资源）**：选 3–5 个公开科学分析 Python/ODE 脚本，人工预注册 25–40 条有明确范围、统计单位、比较量的 claim；构造同范围正确数据、超范围反例、单位/舍入错、换 seed 后失效等 case。比较纯 LLM judge、仅 schema 检查、typed property test、typed test+LLM 声明审核；固定输入、预算及独立 oracle。测 claim-to-test fidelity、覆盖率、false pass/false reject、inconclusive、反例复现率、token/time。**可证伪**：若 typed contract 只能覆盖很少 claim、误判范围边界，或相同预算不优于简单规则，不能声称普遍提高科研验证能力。

**Codex E4e｜自适应更新的累计假阳性（低资源）**：在合成正态均值检验/两组 A/B 测试上让固定模型或规则生成 20–50 个阈值/分析策略更新，比较复用同一验证集、每轮 fresh null 但无跨轮风险分配、fresh null+预注册 lifetime risk gate；固定候选版本、仿真次数与预算。报告每版本 Type I error、**ever-approve-invalid** 概率、功效、拒绝率与验证开销；单独检查 null 情景错配。**可证伪**：若安全收益仅来自不批准任何更新、仿真与真实分布不符，或无法在有限成本维持功效，则不能把数学界限外推为通用科学可信度保证。

**2026-10-26 增量｜Q7：验证对象分离为研究结论、动作合法性、harness 可靠性、judge 稳健性**：[POSEIDON](https://arxiv.org/abs/2610.32448) 从 7110 个公开仓库构建 97659 个可执行环境，提醒大规模科学训练/评测需审计仓库级污染、测试器可信与 task shortcut；[Trial by Trace](https://arxiv.org/abs/2610.32285) 报告 31.1% 任务成功的轨迹仍违反至少一项 harness 准则；[When Agents Fail](https://arxiv.org/abs/2610.32483) 在 52168 条通用轨迹中发现模型×harness 排名交互；[Who Verifies the Tools?](https://arxiv.org/abs/2610.32110) 说明工具格式器缺少边界信息可使 Agent 和 verifier 一起误判。以上大多是通用 agent 证据，**不能把运行可靠性当作科学结论正确性**，但会改变 Q7.3/Q7.5/Q7.6 的评测门槛。

**协议增补**：科学 Agent benchmark 应分别提供 (a) 仓库/任务家族隔离与数据泄漏审计，(b) 工具回执中的权威来源、截断/上限、版本/命名空间，(c) 轨迹 action-constraint oracle，(d) 任务结果与科学 claim 的独立验证。报告 task success、valid completion、harness violation、false release、总 token/wall time；不能仅用模型×harness 的单一总分排名证明发现能力。

**2026-10-27 证据更新｜Q7：评测需要区分事实正确、来源正确、使用资格正确**：[SciValidityBench](https://arxiv.org/abs/2610.34767) 用确定性 oracle、配对反事实与 exact/irrelevant repair 检查跨事件统计约束的实际使用；[AlphaIdeaBench](https://arxiv.org/abs/2610.33644) 则说明 peer-review 对齐是构想 judge 的外部参照而非最终真值。**Q7.3/Q7.4 优先级更新**：单次 final-answer accuracy、引用存在性、静态 reviewer score 不足以衡量科学证据依赖；应将 state-use validity、counterfactual action sensitivity、false confirmation、独立 judge 校准纳入评测。原有 E4d/E4e 继续保留，新增的可执行 E5b 作为 Q5/Q7 联合实验，不另起一套重复 benchmark。

### 2026-10-28 跨领域专题｜Coding Agent 的补丁正确性与评判器可靠性（方法迁移，不新增 Q10）

**讨论背景（非 AI4Science 论文证据）**：Coding Agent 完成 issue 后，**通过原始 tests**、**满足需求**、**与参考补丁行为等价**、**LLM judge 判对**是四个不同命题。参见[研究树 H7-C（11 篇原文与六字段比较）](研究树.md#h7-c-coding-agent-输出正确性评判跨领域方法索引2026-10-28)。这一批 SWE/Code Verification 工作用于借鉴科研代码输出的可靠验收，不能直接将 SWE-bench 的分数/错判比例推广到科学 Agent。

**直接前作与问题边界**：
- **False pass：错误补丁被放行**。[UTBoost](https://aclanthology.org/2025.acl-long.189/) 静态补测试、[SWE-ABS](https://arxiv.org/abs/2603.00520) 变异/对抗增强、[TestJack](https://arxiv.org/abs/2610.10619) 针对具体 trial 的 requirement-driven 动态审计，均已研究，不能再把“自动生成反例测试”当全新 idea。
- **False reject：正确补丁被错误拒绝**。[SWEPatchTest](https://arxiv.org/abs/2610.18004) 要求同时接受正确补丁、拒绝错误补丁；[What the Specification Did Not Say](https://arxiv.org/abs/2610.30635) 发现测试可能依赖任务描述未说的名称/路径；[PatchDiff](https://arxiv.org/abs/2503.15223) 指出差分行为不等于确认错误。**Reference patch 不是完整的独立规范**。
- **Judge 信度和证据**。[CodeJudgeBench](https://aclanthology.org/2026.acl-long.888/) 与 [Don't Judge Code by Its Cover](https://aclanthology.org/2026.findings-eacl.70/) 测语义等价代码变体对 Judge 的干扰；[Agentic Rubrics](https://aclanthology.org/2026.acl-long.697/) 用仓库上下文建评判清单；[Agent-as-a-Judge](https://proceedings.mlr.press/v267/zhuge25a.html) 增加过程审查；[RETRACE](https://arxiv.org/abs/2608.08950) 用正反重建检查 issue–patch 一致性。解释/投票/过程评价仍不是执行级正确性证明。

**对 Q6/Q7 的实际意义**：原 Q6 的“代码执行成功 → 科学结论可靠”与 SWE 的“测试通过 → 补丁正确”存在相似的 **oracle 不完整性**，但科学验证还包含统计方法、独立观测和科学主张，不应混成单个 coding 指标。Q7 可新增一条**跨领域对照维度**：同时报告 False Pass、False Reject、测试真值与规格一致性、judge 语义不变性、可重放的反例、审计成本。相比单纯增加测试数量，优先评价**评判器本身是否可信**。

**Codex 小实验 E4f（讨论与前作复核，不直接当论文创新）**：15–30 个小型真实 Python issue，预注册明确需求，构造多个正确等价补丁及真实错误补丁；测原有 tests、静态 test augmentation、可执行差分、LLM judge、组合审查。固定候选池、模型/工具/总成本；对正确代码加入重命名/注释变体，对需求移除隐含 API 名称，测 false-pass/false-reject、语义变换翻转率、oracle-specification gap、可重放反例比例与耗时。若新增测试误拒正确实现、或所谓成功只来自参考实现的特殊行为，判机制未通过。**前作检查**：按 TestJack、SWEPatchTest、Specification–Oracle Gaps 的已知结果先筛创新性冲突，不能宣称无人研究。


**2026-10-28 增量｜Q7：自由科研发现必须独立测“发现问题→实验支持→规律正确”**：[LongChang](https://arxiv.org/abs/2610.37649) 在不给研究目标的变更物理场景中将 law correctness 与实验支持分开，12 模型中仅 1 模型有非零发现率；把回合上限从 100 提至 500 并未提升其发现率（作者报告），提示异常追查/研究问题选择可能比更多预算更关键。[CogArena](https://arxiv.org/abs/2610.36484) 进一步表明行为科学实验的网页任务完成、得分与行为签名复现是不同测量对象。**饱和度修订**：无预置目标的可执行科学发现基准已出现直接前作；开放问题是异常发现、主动辨别实验、科学主张支持与判定器独立性的逐关口校准，尤其避免仅用 LLM judge 的“支持性”替代可执行 oracle。现有 E4/E4d 可增加正常场景/伪异常负对照，不因两个 benchmark 再创建重复测试集。


**2026-10-29 增量｜Q7/H8：harness 上限与模型-接口失配不能混淆**：[Your Policy Is Secretly a Harness](https://arxiv.org/abs/2610.37255) 将部署表现区分为 harness ceiling 和 checkpoint mismatch；同样的最优动作，观察字段顺序变化也能显著影响已训练模型的成功率。**协议修订**：固定模型对比多个 scaffold 只能说明该 checkpoint 的即时适配表现，不能直接排序 scaffold 的潜在上限。低资源 Codex 可在 20–30 个可执行 Python 科学任务上固定语义与 oracle，仅交换工具字段/回执呈现、控制步骤数、可用动作集合，比较同模型不同接口的选择与错误；以规则/oracle 控制器测试任务可达性上界，**不得**把代理上界称为严格的理论 ceiling。记录 action flip、成功率、额外调用和错误归因。

## Q8. Scientific Agent 如何从跨轮经验中真正学会更好的研究策略？

**问题结构**
- Q8.1 保存失败摘要是否提高下一任务的决策，而不是只增加 token？
- Q8.2 技能／工具自动生长能否迁移到新问题？
- Q8.3 工作流／调度规则演化，与换更强 base model 的贡献能否区分？
- Q8.4 坏经验、工具版本改变和分布外任务是否导致负迁移？

**已见证据**：[EvoScientist](https://arxiv.org/abs/2603.08127)、[HypoForge](https://arxiv.org/abs/2608.25770)、[Test-Time Tool Evolution](https://arxiv.org/abs/2601.07641)、[CORAL](https://arxiv.org/abs/2604.01658)、[Runtime Agent Coordination](https://arxiv.org/abs/2610.00980)。

**缺口判断**：泛称 self-evolving 的文章**较拥挤**，严格时间切分、无记忆对照、跨任务迁移与机制归因较少。对应[研究树 D1–D3、G1、H8](研究树.md#rt-d)。

**2026-10-12 证据与 Codex 小实验**：[Humanize MLE Agents](https://arxiv.org/abs/2610.13494) 提示旧 harness 可能随 backbone 升级变成负收益；这改变了 Q8.3 的评估优先级，但不是新问题。固定一组小型可执行研究任务和总预算，比较原生单会话、同模型上下文重置、同模型双会话接力、异模型交替，以及旧定制 harness × 新旧模型；记录每次实验收益、token/时间、最优产物是否保留和跨任务迁移。**否证条件**：在同预算下重置/交替并无增益，或增益仅来自更多执行次数。

**2026-10-21 证据重审｜Q8：记忆、遗忘、技能、参数更新是不同机制**

[Scaling Discovery Requires Forgetting](https://arxiv.org/abs/2610.20563) 给出主动删除历史可能提升搜索的直接反例；[SwarmRSI](https://arxiv.org/abs/2610.20431) 指向保留失败实验中的局部可用组件；[DiscoveryRSI](https://arxiv.org/abs/2610.23839) 做贡献级信用与 harness replay；[HarnessTTT](https://arxiv.org/abs/2610.17370) 冻结 executor 学 harness；[Coupled Harness–Model Evolution](https://arxiv.org/abs/2610.17740) 分阶段演化工具与模型；[MELD](https://arxiv.org/abs/2610.24454) 则联合学习协调与个体策略。这些都可挂 D1–D3，**不构成无人研究的新问题**；缺口是控制住执行预算的因果拆分及真实任务的迁移可靠性。

**Codex E6｜受控遗忘与可复用失败组件**：在公开的小型可评分算法/科学仿真搜索任务中，设置完整历史、摘要、周期删除（只保留 best artifact）、保留最佳产物+失败组件标签 4 组；固定同一模型、初值、seed、总 evaluator calls、时间和候选池，测 held-out 最佳收益、回访重复率、负迁移与成本。否证：主动遗忘的表面收益来自额外 budget、删掉历史后的 seed 偶然性，或不能迁移到保留真实研究状态的任务。

**2026-10-23 增量证据｜Q8：经验“复用单元”与独立迁移验收**：[ExpEvolve](https://arxiv.org/abs/2610.29303) 从已评分程序抽取可解释 idea factors，并将其用于跨程序结构的探索控制；这是 [CausalEvolve](https://arxiv.org/abs/2603.14575) 的扩展，且高层因子与分数关联不等于因果发现。[ScienceClaw](https://arxiv.org/abs/2610.08691) 在固定基础模型下要求 source-task replay 与独立任务收益才接受 Skill/Operator 更新。**Q8.1/Q8.2 缺口细化**：区分完整程序、失败组件、文本经验、idea factor、可执行 skill 五种经验单元；以独立任务迁移、负迁移和总推理/评测成本判断是否真进化。

**Codex E6b（接续 E6）**：选小型程序搜索或可评分仿真任务，固定初始 archive 和 40–80 次 evaluator 调用，比较程序复制、文本摘要、组件重组、idea-factor 标签引导、源任务 replay+独立测试门控；额外 LLM 标注调用计入总成本。以 unseen task gain、误接受 skill 率、重复探索率和成本作判据。若收益来自更多 LLM 调用或标签与 held-out 无关，则不认定机制独立有效。

**2026-10-24 增量｜Q8：自改进必须区分产品提升、过程可重复、无遗忘迁移**：[Auditing the Product, Not the Recursion](https://arxiv.org/abs/2610.27610) 对 114 项研究编码：90 项自称 RSI 的研究中仅 22% 检查至少两次完整循环重跑，26 项声称改进程序更优者仅 4 项提供同起点同预算比较。[Are Self-Evolving Agents Continual Learners?](https://arxiv.org/abs/2610.25858) 的漂移任务流显示共享 prompt/skill 的全局编辑可能损害旧任务，相似检索亦可能错误迁移。**缺口修订**：Q8 的关键不是能否在单条轨迹改善分数，而是能否在**同一初始产物、相同预算、独立后续任务、至少两次完整循环重跑**下稳定提高改进方法本身。二者是审计/一般 Agent 流的证据，不直接证明科学领域的失败比例。

**Codex E6c（接续 E6/E6b）**：在小型方程发现/仿真程序任务上固定 3–5 个初始状态与 3 个 seed，比较无更新、全局共享 skill 更新、条件化技能库、带 rollback 的局部更新；每组完整重跑整个研究循环并在未见任务流测 gain、retention、negative transfer、improver-to-improver 增益和总预算。若仅终态分数更高但新改进程序在相同初值下没有稳定收益，不认定“学会了更好的科研策略”。

**2026-10-25 证据修订｜Q8：自演化的晋升门槛须与长期风险分离**：[CMAS](https://arxiv.org/abs/2610.31436) 在非平稳模拟环境中使用配对 shadow replay、风险惩罚和 rollback 选择 agent 架构，表明“改进前后的同条件比较”可操作；但其每次晋升错误率不保证多轮风险。[Lifetime-valid decisions](https://arxiv.org/abs/2610.30562) 在限定的统计决策情景下提供跨任意更新轮次的 Type I error 控制，但依赖忠实 null simulator。**Q8.3/Q8.4** 的新控制变量：不仅记录同模型/同预算下每次更新收益，还要记录整个版本序列的误晋升、rollback、验证成本和独立后续任务 retention。可沿用 Q7 的 E4e 先做纯 Python 统计模拟，不把金融/一般 Agent 的结果直接当科学研究证明。

**2026-10-26 增量｜Q8：外部记忆 vs 在线权重更新，及技能“无增益”的歧义**：[TTME](https://arxiv.org/abs/2610.32046) 在两套数学发现框架中以结构化外部记忆替代 TTT，作者报告五项任务结果更好、FLOPs 降 82.8–84.6%、时间降 47.7–58.4%；但 TTT 部分沿用原论文结果，需完整同起点重跑和记忆整理成本归因。[What Transfers Across Protein Pockets?](https://arxiv.org/abs/2610.32620) 发现跨口袋经验索引可能主要捕捉编辑大小而非靶点特异知识；[Beyond Gain](https://arxiv.org/abs/2610.32322) 说明 skill gain≈0 可能是**已内化**，也可能是**完全未覆盖**。Q8.1/Q8.2 的重要新变量：经验索引是否指向任务机制、记忆/技能是否在未见任务上产生可归因收益、skill 退休后是否真的保持能力。

**Codex E6d｜轻量经验复用与错退役消融**：固定小型符号回归/可评分优化任务与初始候选池，比较无记忆、原始轨迹检索、文本总结、分层策略记忆、按任务条件索引的策略记忆；额外设计“模型本来会做”和“模型与技能都不会做”的 skill-retirement 反例。固定候选执行数、token 及整理成本，跨未见任务评估增益、负迁移、误退役率和每单位总成本。**不以此低资源实验声称完成 TTT 权重更新的同预算复现**；若经验仅帮助重复题、检索键是非因果代理或成本收益消失，则不认为学到了可迁移科研策略。

**2026-10-27 证据更新｜Q8：随机实验结果会被写成错误经验；技能收益与执行器能力交互**：[Lessons from Luck](https://arxiv.org/abs/2610.33029) 的预注册合成实验固定工具真实可靠性、随机赋予偶然失败，随后 lesson 让下一轮选择较差工具的比例从 0.4% 上升至 11.6%（作者报告）；这比“记忆会负迁移”的一般论述更明确定位了**outcome noise→memory writing→wrong action** 的因果链。[Skill Adaptation](https://arxiv.org/abs/2610.33024) 发现同一 skill 对强/弱模型可能产生相反效果，并用 executor-capability 匹配的技能改写改善弱模型；[Organon](https://arxiv.org/abs/2610.33046) 还展示修订自身修订过程，但没有逐项因果消融。**缺口修订**：Q8.1/Q8.4 的关键不只是是否保留/遗忘经验，而是**对结果噪声校准、条件适用性与模型可执行性**；不把单任务改善等同长期科学持续学习。

**Codex E6e｜偶然失败污染与技能能力错配**：在 20–30 个小型仿真/工具选择世界中固定两个工具的真实期望效用，随机注入偶然失败/成功；比较无记忆、结果摘要、记录“决策质量与结果噪声”的因果 lesson、统计证据门控的经验入库。另用强/弱模型同一技能描述和简化版本交叉测试。固定独立 held-out world、模型/调用次数与总 token；测次轮 regret、错误策略迁移率、误采纳/误退役和技能执行失败率。**否证**：如果改进仅由给模型额外真实可靠性信息、更多 token 或简化格式产生，不认定经验归因机制具有独立收益。


**2026-10-28 增量｜Q8：自我改进需先扣除择优噪声和额外轨迹成本**：[BiPA](https://arxiv.org/abs/2610.37201) 以完全相同 seed skill 的候选回放接受规则，发现小 dev 集的“优化收益”可能由 best-of-N 选择噪声产生，且规则膨胀增加约 16% 输入 token（通用 Agent，作者报告）；[Dream-COP](https://arxiv.org/abs/2610.36618) 已用旧搜索轨迹离线重放学习策略，不能把“经验重放”本身称新颖。**优先级修订**：Q8.3/Q8.4 的因果评测应先控制 no-op candidate、重复抽样、真实独立 test 与按 turn 重发上下文的总成本，再讨论自演化/跨任务迁移。

**Codex E6f｜科研 skill 优化的 selection-only 负对照（低资源）**：选 12–20 个可执行科学 Python 任务与固定 2–3 个原始 skill，比较原 skill、完全不改写但重复择优、真实编辑、随机编辑、oracle 选择；开发集/测试集按任务族隔离，记录每轮完整上下文 token、工具调用、wall time、独立 test 的有效改进。**否证**：若编辑收益不超过 no-op best-of-N 的虚假提升，或总成本更高而独立正确率不升，则不能声称持续科研策略学习。与 BiPA 直接前作的区别必须是科研任务的独立机制/科学结论 oracle，而不是换数据集名称。


**2026-10-29 增量｜Q8：搜索反馈与最终选择需要分别预算**：[EvalAlloc](https://arxiv.org/abs/2610.37276) 已明确区分演化搜索期的稀疏评价与最终候选确认，并通过共享评价项/配对 successive halving 复用信息。**E6f 补充**：在不调用 GPU 的离线候选×科学任务得分矩阵（30–50 candidates × 20–40 tasks，含任务难度/评分噪声/相关错误）中，比较 full evaluation、随机稀疏评价、共享配对评价、搜索后独立确认、no-op best-of-N；固定总 evaluation cells，再单独统计模拟的 token/CPU 成本，评估独立 test regret 与 winner's curse。若收益仅来自更大的选择预算或未见任务族上消失，不认定学到了科研策略。论文原实验在通用 QA/指令遵循和 8×H20 服务器上完成，不应直接外推科学实验。

## Q9. 人类科学家应该在什么时候介入？

**问题结构**
- Q9.1 人类负责定 research question、批实验、解释冲突证据，还是最后签名？
- Q9.2 Agent 能否在高风险／高成本／证据冲突时请求专家，而非定期打断？
- Q9.3 同预算下，选择性专家介入能否优于全自动或固定阶段审查？

**已见证据**：[Agent Laboratory](https://arxiv.org/abs/2501.04227)、[Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y)、[AIMC](https://arxiv.org/abs/2608.28637)、Robin。完整真实实验常有人工步骤，不能误称无人闭环。对应[研究树 I1–I2、H5](研究树.md#rt-i)。

## 选题交给 Codex 前的统一关口

只有通过以下检查，才从**灵感**升级为**实验候选**：

| Gate | 必须回答 |
|---|---|
| G0 研究问题 | 具体失败模式是什么？已有论文做到哪一步？为什么不是已有机制换名字？ |
| G1 可证伪假设 | 什么观测会证明这个 idea 不成立？ |
| G2 基线与协议 | 最相近 2–3 条路线、最简单 baseline、相同模型/工具/预算、公平独立真值是什么？ |
| G3 最小实验 | 是否能用公开代码／合成故障／模拟先验证？是否避免长时 GPU 训练和实体实验？ |
| G4 结论边界 | 成功能证明什么，不能证明什么？失败应回写哪个问题节点？ |

**给 Codex 的最小实验 brief**：问题编号 + 对应研究树节点 + 可证伪假设 + 最相关论文链接 + task / dataset + baselines + controlled variables + metrics + failure criterion + execution budget + evidence artifacts。缺任何关键项时先补研究设计，不直接启动长训练。

## 每日增量维护规则（只维护这两棵树）

1. 先读[研究树](研究树.md)已有机制和本问题树的 gap，再查 24–72 小时论文；按**首次提交／版本日期**判定“新”，不能把旧稿重推当成新论文。
2. 每个候选先判断：不收录／补已有机制证据／更新已有问题的 gap 结论／只有真的改变问题定义时加节点。
3. 若只改善模型、prompt、普通 RAG、角色数、或没受控对照，不凭包装长枝；若有反例必须修正旧的“拥挤/稀缺”判断。
4. 每篇进入树的新论文需包含 **Problem / Core mechanism / Compared with / Tree position / Genuine addition / Evidence limitation** 和原文链接。
5. **两棵树之外的旧文件只作历史证据**；每日不新增论文清单、日报、单篇摘要。没有重要增量时不改文件、只报告“无结构性更新”。
6. 更新顺序：**先研究树（证据与方法差异），再问题树（是否改变 gap、优先级或实验）**；绝不因为新增一篇论文就自动生成一个新“研究问题”。
