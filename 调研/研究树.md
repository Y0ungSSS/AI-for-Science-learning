# AI for Science Research Tree

> Baseline: 2026-09-26  
> 这棵树按 **Research Problem → Mechanism** 组织，而不是按系统名字组织。

---

## 0. 总体闭环

```text
Scientific Goal / Question
        ↓
1. Knowledge & Evidence Acquisition
        ↓
2. Hypothesis / Idea Generation
        ↓
3. Evaluation & Selection
        ↓
4. Research Search / Strategy Control
        ↓
5. Execution
   code / data / simulation / experiment
        ↓
6. Result Analysis & Belief Update
        ↓
7. Research State / Memory / Provenance
        ↺
```

真正的 AI Scientist 不只是能依次跑完这些步骤，而是能根据证据决定**继续、回退、验证、换路线或停止**。

---

# A. Scientific Ideation：怎样产生值得执行的研究假设？

## A1. Literature-grounded hypothesis generation
目标：从文献和已有证据中生成可测试的 hypothesis。

代表：
- Co-Scientist
- Robin
- Agent Laboratory

现状：已经非常拥挤。单纯“检索文献 → 生成若干 idea”不再足以构成明显研究增量。

## A2. Multi-candidate generation + critique / debate
目标：通过并行候选、self-critique、scientific debate 提高 idea 质量。

代表：
- Co-Scientist：Generation / Reflection / Ranking / Evolution，多 agent + tournament。
- The AI Scientist 系列：通过迭代 refinement 生成研究方向。

**判断**：属于成熟机制簇。新论文若只是增加 critic 数量或多 agent 角色，不单独长枝。

## A3. Novelty assessment
问题：一个 idea 到底“新不新”？

代表机制：
- LLM-as-a-Judge
- literature retrieval + similarity
- Relative Neighbor Density (RND)

代表论文：
- *Enabling AI Scientists to Recognize Innovation*（RND）

**仍缺**：novelty ≠ usefulness ≠ soundness。 novelty evaluator 很容易被错误当成 research quality evaluator。

# B. Pre-execution Evaluation：这个想法值不值得执行？

这是当前最重要的独立分支之一。

## B1. Soundness / methodological viability
问题：在花费大量计算与实验资源前，能不能识别方法论上就不成立的 idea？

代表：
- SoundnessBench

已知现象：frontier LLM 存在 optimism bias，不能可靠充当独立 first-gate evaluator。

## B2. Ideation → execution gap
问题：idea 看起来很好，真正执行后是否仍然好？

代表：
- *The Ideation-Execution Gap*

关键认识：仅在 idea 阶段让人或 LLM 打分，可能系统性高估 AI-generated ideas。

## B3. Candidate comparison / ranking
机制簇：
- absolute scoring
- pairwise comparison
- tournament / Elo
- rubric-guided scoring

代表：
- Co-Scientist：tournament ranking
- SciNav：Frontier Comparator，relative judgment 引导 Top-K search

**开放问题**：什么时候 relative ranking 真能替代 ground-truth metric？比较器自身错误如何积累？

---

# C. Research Search & Strategy Control：科研不是反复改 A，而是何时转向 B？

这是当前最值得持续跟踪的方向之一。

## C1. Local iterative refinement
```text
A → A' → A'' → A'''
```

典型机制：
- self-reflection
- self-debug
- evaluator-guided refinement

问题：容易停留在同一策略附近。

## C2. Multi-trajectory / tree search
```text
        A
      / | \
    B   C   D
   / \     / \
 ...
```

代表：
- The AI Scientist-v2：progressive agentic tree search
- ERA：tree search over candidate scientific software
- SciNav：Top-K Comparative Tree Search

### 三者差异
- AI Scientist-v2：面向端到端研究实验管理；
- ERA：前提是 task 有明确 machine-scorable objective；
- SciNav：无 ground-truth score 时用 relative comparison 选择 frontier。

**仍缺**：多数 tree search 解决的是“在已有候选中搜索”，还不等于真正理解“为什么失败、该换哪种研究策略”。

## C3. Backtracking / plateau handling
ERA 已证明保留候选树可以在某条 code mutation 路线 plateau 后回退。

但当前大量系统仍缺：
- plateau 的因果诊断；
- “继续调参”与“换方法”之间的决策；
- rollback 的可靠触发规则。

## C4. Goal / objective evolution
代表：
- SAGA（Scientific Autonomous Goal-evolving Agent）

核心变化：
```text
传统：
human defines objective → agent optimizes objective

SAGA：
outer agent observes outcomes
        ↓
changes / creates objectives
        ↓
inner optimizer searches solutions
```

这是比普通 tree search 更值得单独保留的节点，因为它开始搜索**目标函数本身**。

## C5. Strategy switching / meta-reasoning  ★ OPEN
目标：Agent 能明确判断：
- 当前方法只是实现错了？
- hypothesis 错了？
- metric 错了？
- objective 本身错了？
- 应该继续 / 回退 / pivot / stop？

目前尚没有一个公认、成熟的通用机制解决这个问题。

# D. Scientific Execution：把 idea 变成真正可运行的研究

## D1. Scientific coding
代表：
- ERA
- ScienceAgentBench
- SciNav
- RExBench

这里要区分三种任务：

### D1.1 从自然语言任务生成科学分析代码
ScienceAgentBench。

### D1.2 在既有论文代码上实现新的 research extension
RExBench。

### D1.3 自动搜索更优 scientific software
ERA。

**重要**：普通 SWE benchmark 与 scientific coding 不完全相同。科研代码还要求方法与 scientific claim 对齐。

## D2. Data analysis
代表：
- Robin / Finch
- AstaBench 中 data-driven discovery tasks

开放问题：
- 多种合理 preprocessing / filtering / statistical choice 会导致不同结论；
- stochastic analysis trajectory 如何形成可靠 consensus；
- 结果解释错了，还是代码错了？

## D3. Simulation / computational experiment
适合作为低资源 AI Scientist 研究 sandbox。

优势：
- 可自动执行；
- 可复现；
- 可得到 machine-checkable evidence；
- 不依赖真实 wet lab。

这也是适合长期关注的实验载体。

## D4. Physical / wet-lab execution
代表：
- Robin 的 lab-in-the-loop
- Co-Scientist 的生物实验验证

意义很强，但不适合作为低资源方法学研究的默认实验条件。

# E. Result Analysis & Scientific Update：做完实验后，Agent 学到了什么？

## E1. Result interpretation
问题：从结果得出什么 claim？

FIRE-Bench 的 failure analysis 显示，错误并不只来自 coding，planning 与 analysis 同样是主要瓶颈。

## E2. Hypothesis update
代表：
- Robin：实验结果 → 下一轮 therapeutic hypothesis
- closed-loop discovery systems

开放问题：很多系统虽然“循环了”，但缺少对 belief change 的显式表示。

## E3. Failure attribution  ★ OPEN
失败来源可能在：
```text
hypothesis
literature evidence
experiment design
implementation
data
metric
analysis
evaluator
```

需要把 end-to-end failure 分解为能指导下一步 action 的诊断信号。

FIRE-Bench 的 error taxonomy 是重要起点，但“评测后归因”仍不同于“agent runtime 中自主归因”。

## E4. Belief update / evidence aggregation  ★ OPEN
理想状态不是简单保存“上一轮结果”，而是：

```text
Hypothesis H
├─ supporting evidence
├─ opposing evidence
├─ uncertainty
├─ failed tests
└─ next discriminating experiment
```

目前通用 AI Scientist 对这一层仍处理得很弱。

# F. Research State / Memory / Provenance：长期科研状态怎么保存？

## F1. Conversation memory
最简单，但不能作为可靠科研状态。

## F2. Explicit research state  ★ OPEN
至少应保存：
- hypotheses
- evidence
- decisions
- failed attempts
- experiment configuration
- code / data version
- evaluator output
- uncertainty

## F3. Provenance / trace
目标：最终 claim 可以向后追溯到：
```text
claim
→ analysis
→ result
→ code
→ experiment config
→ data
→ hypothesis / decision
```

相关代表：
- Data-to-Paper：backward-traceable research
- Verification Gap survey
- *The More You Automate, the Less You See*

后者的重要结果是：只看最终 paper 很难发现 benchmark selection、data leakage、metric misuse、post-hoc selection bias；完整 trace / code 显著有助于发现问题。

# G. Evaluation & Verification：到底怎样证明 AI Scientist “真的会科研”？

这一分支目前增长最快。

## G1. Component capability benchmark
### ScienceAgentBench
102 个来自真实论文的 data-driven tasks；强调 program execution、结果与 cost。

### LABBench2
更现实的 biology research tasks，测真实科学工作能力。

价值：能定位局部 capability，但不能直接证明 end-to-end discovery。

## G2. Research extension benchmark
### RExBench
给论文、代码库和新的 extension instruction，要求 agent 真正实现研究扩展。

价值：比普通 code generation 更接近“继续做科研”。

## G3. Full-cycle rediscovery
### FIRE-Bench
给 research question，隐藏原论文方法与结论，让 agent 重新：
```text
plan → implement → execute → analyze → claims
```

用已发表研究的 verified result 作为 ground truth。

这是目前非常值得保留的 evaluation paradigm，因为兼顾：
- open-ended exploration
- executable experiment
- externally verifiable claim
- fine-grained failure analysis

## G4. Holistic scientific-agent benchmark
### AstaBench
覆盖文献理解、data understanding、planning、tool use、coding、search 等 2400+ tasks，并控制工具和 inference cost。

它的重要贡献不只是题多，而是 **evaluation protocol**：
- standardized environment
- controlled tools
- cost accounting
- multiple agent architectures

## G5. Proposal-stage evaluation
- SoundnessBench：soundness
- RND：novelty

说明“科研质量”需要拆成多个独立轴，而非一个 LLM score。

## G6. Final-paper / LLM review
方便，但风险最高。

问题：
- judge bias
- model dependence
- style/format confound
- final paper 隐藏过程性错误

因此应作为某一层 evidence，而不是唯一 evaluator。

## G7. Process / trace-based evaluation  ★ OPEN
未来更值得看：
```text
final outcome
+
trajectory
+
decision points
+
resource/cost
+
evidence provenance
```

# H. Human–AI Collaboration

## H1. Human-in-the-loop
Co-Scientist、Agent Laboratory、Robin 都保留不同程度的人类控制。

## H2. Scientist-in-the-loop
真正值得研究的问题不是“有没有人工”，而是：

- 人应该在哪些 decision point 介入？
- 哪些 decision 可以自动化？
- 什么时候系统应主动请求 expert input？
- 如何避免人只是最后替 AI 擦屁股？

当前还没有稳定的标准范式。

# I. 当前研究树的结构判断

## 已经比较拥挤
这些方向如果只有小改进，不应轻易新建分支：
- multi-agent role decomposition
- RAG / literature search
- self-reflection
- generic critic
- candidate ranking
- ordinary tool use
- single-path iterative refinement

## 正在快速形成论文簇
值得每日追踪：
1. scientific coding / research extension；
2. verifiable full-cycle evaluation；
3. pre-execution soundness / idea evaluation；
4. tree / multi-trajectory research search；
5. trace-based reliability。

## 仍明显稀缺的核心问题
### ★ P1 Strategy Switching
什么时候放弃当前 research strategy？

### ★ P2 Failure Attribution
失败后到底应该改哪一层？

### ★ P3 Belief Update
新证据怎样改变 hypothesis state？

### ★ P4 Research State / Provenance
长期研究轨迹如何结构化、恢复和审计？

### ★ P5 Model vs Scaffold
提升到底来自更强 base model，还是 agent scaffold / search / tools？

### ★ P6 Evaluation Protocol
如何在防 contamination、可执行、成本公平、开放式探索之间取得平衡？

# J. 每日新增论文的挂树规则

对任何新论文依次问：

1. 它解决哪个节点的问题？
2. 它与已有论文相比到底改变了什么变量？
3. 新意是：
   - problem？
   - mechanism？
   - evaluator？
   - benchmark？
   - real-world validation？
4. 如果拿掉论文包装，它是否只是已有机制重新组合？
5. 是否改变当前对某个 Open Problem 的理解？

只有第 3 或第 5 项有明确答案，才值得正式进入这棵树。
