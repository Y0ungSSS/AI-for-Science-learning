# 调研 · 两棵树

本目录只需要读两个文件：

- **[问题树.md](问题树.md)**：从“科研哪里还不可靠”出发，呈现开放问题、已有证据、研究缺口及可证伪的 Codex 小实验；这是**找选题和决定做什么**的入口。
- **[研究树.md](研究树.md)**：从“别人已用什么机制解决问题”出发，呈现同类论文、方法差异、代表性基线、验证协议和证据限制；这是**比较已有工作和选 baseline**的入口。

## 怎样使用

**发现灵感**：在问题树找到 Q 编号 → 顺链接看研究树的 A–I 对应机制 → 检查最近 2–3 个 anchor 的真正差异 → 用问题树给出的 Gate G0–G4 明确可证伪假设 → 再让 Codex 执行小实验。论文机制的“新”不等于科学结论的“可靠”。

**每日增量**：先比对现有两树，广搜过去 24–72 小时的 AI for Science / AI Scientist 新论文，回到原论文核验后才做判断：

1. 只是新包装、常规多 agent／RAG／critic／prompt → **不长枝**；
2. 已有问题和已有机制的更强结果／失败反例 → 在**研究树**补证据并说明实验边界；
3. 真正改变搜索/判断/执行/评测机制 → 在**研究树**的适当位置新增或拆分子簇；
4. 新论文改变了什么问题**仍未解决**、是否值得实验 → 同步更新**问题树**的 gap／实验建议；
5. 只有确认出现新的科学方法学问题，才增加问题树一级节点；若当天没有有意义的内容，**不改文件**。

每日只写 `问题树.md` 和 `研究树.md`，不再额外维护日报、论文池、语料库。旧文件留存用于查证，**无需日常阅读**，也不删除历史。可以在两树末尾留一两句重要的更新记录，但不因日期变化反复改文件。

## 证据等级与安全边界

- **论文报告**：作者在论文中声称的结果，不等于我们复现。
- **研究树判断**：根据多篇论文作机制比较，允许后续证据推翻。
- **实验候选**：拟交 Codex 的研究设计，未运行前不写成实证结论。
- **优先低资源**：公开代码、可执行 benchmark、可复现模拟、有限推理预算；真实 wet lab 与长 GPU 训练只作为拓展，不是默认门槛。

历史 baseline：2026-09-26 建树，后续语料累计至 **119 篇**；所有历史资料仍在本目录和原仓库，后续不需要每天更新计数。
