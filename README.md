## 研究工作流

1. 在**问题树**明确 Q 节点、真实使用场景、可证伪假设。
2. 在**研究树**找最近的 2–3 个机制 anchor，排除已有工作覆盖。
3. 定义可执行任务、独立真值、基线、资源预算与失败条件。
4. 先做小型预实验，再决定是否正式立题；不能将作者报告当作自行复现。
5. 有新机制证据时更新研究树；只有开放问题判断发生实质变化时更新问题树。

## 内容分工

- **活跃研究状态**：`调研/问题树.md`、`调研/研究树.md`。日常自动调研只维护这两个文件。
- **历史证据资料**：`调研/论文语料库.md`、`调研/论文池.md`、两份 2026-09-26 大调研和`调研/更新记录.md`。保留原貌；历史数量与日期不能当成实时统计。
- **教学与专题笔记**：`01_foundations/` 至 `11_learning-notes/`、`papers/`、`glossary.md`、`roadmap.md`。用于建立知识依赖和精读，不与双树争夺“当前结论”地位。
- **旧候选工作流**：`radar/` 为历史参考，不是当前自动任务的写入目标。

## 证据原则

区分**论文作者声称、已核验原文、独立复现、研究假设**。机制新颖性、科学正确性和评测分数不能互相替代。优先选择公开代码、CPU 可运行的模拟、可审计的 oracle 与同预算对照。

> 历史研究树的 A–I 与问题树的 Q1–Q9 是导航体系，不代表研究问题已经穷尽。结构调整必须有实质机制或反证支持。
